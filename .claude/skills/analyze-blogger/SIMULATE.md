# 博主仓位模拟 Skill

基于博主的**公开仓位披露**，模拟其组合净值曲线。当博主帖子中包含**具体仓位构成**（标的 + 占比）和**操作记录**（买入/卖出/加减仓点位和仓位）时，可以独立于其方向判断信号，还原其真实账户表现。

---

## ⚠️ 适用范围

**SIMULATE 仅适用于公开披露仓位的博主**。绝大多数财经博主只发表"看多/看空"观点，不公布具体持仓标的和占比——这类博主**不适用**本 Skill，仅使用 `SKILL.md` 的方向信号评分体系即可。

当前 11 位博主中：

| 博主 | 适用 SIMULATE? | 原因 |
|:---|:---|:---|
| **顺应周期** | ✅ 适用 | 每帖均披露具体仓位构成（标的+成数），操作记录完整 |
| 其余 10 位 | ❌ 不适用 | 仅发表方向性观点，不公布持仓标的和具体比例 |

> **判断标准**：博主的帖子中是否同时满足以下三个条件——
> 1. 明确列出持仓标的（如"银行""创业板""中证500"）
> 2. 标注各标的仓位比例（如"1成""3成"）
> 3. 披露频率 ≥ 每周 1 次
>
> 三个条件缺一不可。仅说"仓位5成"不提标的 → 不适用；仅说"看好券商"不给比例 → 不适用。

---

## 前提条件

- 博主在帖子中**公开披露仓位**：持仓标的 + 各占比（如"1成银行""3成创业板"）
- 博主披露**操作记录**：买入/卖出/加减仓的具体点位和仓位
- 博主披露频率足够追踪仓位变化（至少每周 1 次）
- **可投资标的仅限以下 2 个指数**：上证50(000016) 和 中证1000(000852)

## 提取流程

### Step 1: 关键词预筛（正则粗滤）

从全部帖子中筛选出**可能包含仓位信息**的帖子。这一步用正则做，目标是**宁可多筛、不可遗漏**——误筛的帖子 LLM 在下一步会自行判断为"无仓位信息"。

**原始数据**：`data/posts/<博主名>.json`，全部帖子。筛选目标时间范围内的帖子（如 2026-01-01 起）。

**正则模式**（匹配中文字符，不做打分排序）：

```python
import re

# 仓位量词 — 提到"几成"或仓位状态
has_units = (
    r'成|'                 # 兜底：任何含"成"的表述（1成/一成/成仓/几成/成本/完成…噪音由LLM过滤）
    r'\d+层|'             # X层（部分博主用"层"代替"成"）
    r'[一二三四五六七八九十两]\s*层|'  # 一层, 两层...
    r'半仓|满仓|空仓|重仓|轻仓|底仓|总仓位|总仓|'
    r'仓位'                # 任何提到"仓位"的帖子
)

# 操作动词 — 发生了真实交易
has_action = (
    # 基础买卖（含"了""掉"确认完成）
    r'进了|减了|抛了|加了|买了|卖了|'
    r'买进|卖出|买入|'
    r'出了|出掉|抛掉|跑了|跑掉|'
    r'减掉|加进|抛出|接回|'
    # 仓位调整
    r'补仓|减仓|加仓|建仓|清仓|平仓|锁仓|'
    r'调仓|换仓|移仓|调入|调出|'
    r'减到|加到|降至|增至|'
    # T操作（日内买卖，净仓位不变）
    r'T了|T掉|做T|'
    # 回补
    r'回补|补了|补进|接了点|'
    # 止盈止损
    r'止盈|止损|割肉|'
    # 进出场
    r'进场|离场|上车|下车|梭哈|打满|'
    # 数字+操作（"进1成""减2成"，无"了"）
    r'[进减加抛出补]\d|'
    r'[进减加抛出补][一二三四五六七八九十两]'
)

# 持仓描述 — 在描述自己当前持有状态
has_holding = (
    r'持仓|持有|拿着|在场|在场内|'
    r'我还有|还剩|剩下|留有|保留|'
    r'底仓|仓位管理|仓位结构|'
    r'配置|配比|组合|'
    r'防守仓|进攻仓|短线仓|中线仓|长线仓|'
    r'目前仓|当前仓|现在仓|我的仓|个人仓|'
    r'%仓位|仓位%'          # "50%仓位" 表述
)

pattern = re.compile(f'{has_units}|{has_action}|{has_holding}')

# 筛选
candidate_posts = [
    p for p in all_posts
    if p['publish_date'][:4] >= '2026'
    and pattern.search(p['content'])
    and len(p['content']) > 15  # 过滤过短帖子（纯表情/打招呼）
]
```

> **为什么要预筛？** 博主每天发帖 ~6 条，一年 ~2000 条，其中大部分是纯市场评论（"大盘震荡""板块轮动""注意风险"），不含任何仓位信息。全文送入 LLM 成本高且无必要。预筛将候选集从 ~2000 压缩到 ~200，LLM 只需处理这 200 条。

**预筛效果**（以顺应周期 2026 年为例）：

| 阶段 | 帖子数 |
|:---|:---|
| 原始全部帖子 | 2394 |
| 2026 年帖子 | 741 |
| 关键词预筛后 | ~233 |
| → 送入 LLM 提取 | ~233 |
| → 结构化快照输出 | 由 LLM 判定 |

### Step 2: LLM 结构化提取

将 Step 1 预筛出的全部候选帖子送入 LLM，逐条判断是否包含仓位信息，对包含的帖子提取结构化仓位快照。

**LLM 输入**：
- 预筛后的全部帖子（含 `post_id`、`publish_date`、`content`）
- 标的映射表（见上方"标的映射规则"）
- 提取规则（A/B/C 分类 + 意图过滤 + 同日全部保留 + T 操作）

**LLM 输出**：一个 JSON 数组，每个元素是一个仓位快照。

> **⏀ 核心约定：所有快照的 `positions` 字段必须是绝对仓位（当日终态），不是增量。**
> 模拟引擎直接替换，不做叠加。例如 "加了1成综指" → LLM 输出的是加完之后的完整持仓，不是 `{"000852": 1}`。

**LLM 需要执行的判断**：

**A. 确认持仓报告**（直接映射）：
```
博主逐项列出当前持仓的标的 + 占比，LLM 直接映射为指数单位数。

> **模拟引擎执行流程（A 类）**：
> 1. 收到 explicit 快照 → positions 直接替换 current_pos，不计算不修正
> 2. 按新 positions 计算当日起的 NAV

例 → explicit:
  "目前仓位是1证券，1保险，1白酒，1双创，1创业板，3上证综指，共8成仓"
  → 证券+保险+白酒→上证50(3), 双创+创业板+综指→中证1000(5)
  → {"000016":3, "000852":5}

  "目前仓位是3成宽基+2成金融"
  → 金融→上证50(2), 宽基→中证1000(3)
  → {"000016":2, "000852":3}
```

**B. 交易操作**（LLM 给绝对单位，引擎在权重空间修正）：

```
博主只说了刚发生的操作，未列出完整持仓。LLM 结合前态推导新持仓（仍以绝对单位输出）。

⚠️ **关键：B 类操作必须在权重空间执行。** 两个快照之间指数涨跌已改变前态各标的
的实际仓位。LLM 输出的单位数只是"参照前态 +X unit"的静态推测——模拟引擎收到后，
会计算当前实际市值权重，在权重空间叠加操作，再转回单位数。

模拟引擎执行流程：
1. 检测 LLM 输出的 inferred 快照与前态的 unit 差异（Δunits）
2. 计算前态各标的的**当日实际仓位** = Σ(units × cum_return) / NAV（成）
3. 将 Δunits 转为仓位变动：Δ成 = Δunits × cum_return[code] / NAV
4. 新仓位 = 实际仓位 + Δ成
5. 转回 units: new_units = 新成数 × NAV / cum_return[code]
6. 其余标的 units 保持不变

关键规则：操作动词 + 量词但**未指定标的**时，默认标的 = 中证1000（000852）。

例1 → inferred（指定了标的）:
  前态: {"000016":4}, total=4。之后 000016 涨 5%, NAV 涨到 1.02。
  当前实际仓位: 000016 = 4×1.05/1.02 = 4.12成
  帖子: "刚好3870点，进了1成上证50"
  → LLM 输出 {"000016":5}（前态 +1 unit）
  → 引擎检测到 000016 +1 unit → 权重空间 +1成 → 目标 = 4.12 + 1.0 = 5.12成
  → new_units = 5.12 × 1.02 / 1.05 ≈ 4.97
  结果: {"000016":4.97}, total≈4.97

例2 → inferred（未指定标的，默认中证1000）:
  前态: {"000016":2}, total=4
  帖子: "本人加了1成"，无标的 → 叠加到 000852
  结果: {"000016":2, "000852": 实际仓位+1成转换后的 units}, total 相应更新

例3 → inferred（未指定标的，默认中证1000）:
  前态: {"000016":2, "000852":2}, total=4
  帖子: "在4120减了2成出来"，无标的 → 从 000852 减 2成
  结果: 000852 的 units 减少到对应减 2成后的水平
```

**C. 仅报总仓位**（不涉及操作动词）：
```
博主只说了总成数，**无任何操作动词**。
→ LLM 不填 positions（留空），total_units 设为博主报的数字。

> **模拟引擎执行流程（C 类）**：
> 1. 计算前态在当前市值下的**实际总成数**：actual = Σ(units × cum_return) / NAV
> 2. 按 scale = new_total / actual 缩放各单位
> 3. 各标的等比例缩减或扩张，总成数精确匹配博主报的数字

例1 → partial:
  帖子: "仓位降到4成"
  → positions 留空, total_units=4

例2 → partial:
  帖子: "本人继续4成仓位"
  → positions 留空, total_units=4

例3 → partial:
  帖子: "现在一共7成"
  → positions 留空, total_units=7
```

**意图过滤（关键）**：
以下表述**不算**实际仓位变化，LLM 必须跳过：
- 计划/预期：`"计划加仓""打算在X点进""如果跌到X就加""明天准备减"`
- 挂单未成交：`"挂单中""挂着了""等成交"`（确认"已成交""成交了"才算）
- 纯建议：`"建议大家""可以考虑""个人觉得"`

**同日多帖**：
同一日期多条帖子各自记录独立操作时，**全部保留**，按 `publish_time` 排序。模拟引擎会逐条处理——每条仓位变化都产生一条 trade_log 记录；每日最终仓位用于 NAV 计算。

**T 操作处理**：

`"T了X成"` 或 `"T掉X成"` 表示博主做了当日 T+0 交易——同一日内先买入后卖出（或先卖后买）X 成，赚取日内价差。LLM 需要结合当日其他帖子判定 T 的净仓位影响：

**情形 1 — T 前有同日买入操作**（仓位需回撤）：
```
早盘 "进了1成创业板" → 总仓位 +1成
午盘 "把早盘进的1成T掉了" → 早盘的 +1成 被 T 掉，仓位回到早盘买入前的水平
```
→ LLM 输出一条快照：`total_units` 回退到早盘操作前的值，`description` 记录 T 操作。

**情形 2 — 当日无前序操作，仅描述性 T**（仓位不变）：
```
"今天T了1成，赚了点差价"
```
→ 全日仓位不变，LLM 可选跳过或输出与前态相同的快照（引擎会记录 type="T" 的 trade_log）。

> **核心**：LLM 需理解同日内帖子序列。T 如果是对早盘已有操作的平仓，则仓位回撤；如果只是事后描述当日做过 T、没有提到具体买卖标的和方向，则仓位不变。判断依据是当日同标的**是否先有加仓/减仓信号**然后才出现 T。

**不可映射标的**：
无。所有博主的通俗标的名称均可映射到上证50(000016) 或中证1000(000852)。`unmapped` 字段始终为 `{}`。

### Step 3: 时间线构建

按 `publish_time` 排序所有快照，构建仓位变化时间线。每个快照包含：

- **日期**：`publish_date`
- **原文描述**：帖子中的原始仓位表述
- **映射后仓位**：使用指数代码（000016/000852）作为 key
- **总仓位**：各标的成数之和
- **现金**：10 - 总仓位成数
- **置信度**：`explicit`（标的+比例均明确）/ `inferred`（从操作反推）/ `partial`（仅总仓位）

```json
{
  "position_snapshots": [
    {
      "date": "2026-07-13",
      "publish_time": "2026-07-13 15:32",
      "post_id": "1872106396637194",
      "description": "1银行+1保险+1券商+1药+1酒",
      "positions": {
        "000016": 3.0,
        "000852": 2.0
      },
      "unmapped": {},
      "total_units": 5.0,
      "cash_units": 5.0,
      "confidence": "explicit"
    },
    {
      "date": "2026-02-03",
      "publish_time": "2026-02-03 14:58",
      "post_id": "1856086337902857",
      "description": "早盘4000附近进的2成先T了，还剩4成，2成有色和2成银行",
      "positions": {
        "000016": 2.0,
        "000852": 2.0
      },
      "unmapped": {},
      "total_units": 4.0,
      "cash_units": 6.0,
      "confidence": "explicit"
    }
  ]
}
```

> **字段说明**：
> - `publish_time`（必填）：从原始帖子中获取的完整时间戳 `YYYY-MM-DD HH:MM`，用于判定参考价格
> - `positions` 的 key 统一使用指数代码（000016 或 000852），与映射表一致
> - `unmapped`：始终为 `{}`，所有标的均可映射到上证50 或中证1000
> - `total_units` = Σ positions.values() + Σ unmapped.values()，1 unit = 1成 = 组合的 10%
> - `cash_units` = 10 - total_units，现金不产生收益
> - `confidence` 区分数据质量，见 Step 2 末尾说明

### Step 4: 净值模拟

参考 `scripts/simulate_nav.py`：

1. 初始化：NAV = 1.0，快照指针指向最早的仓位记录
2. 按交易日逐日遍历，对每个交易日：
   a. 收集该日所有生效的快照（按 `publish_time` 排序），解析每条快照的参考价格
   b. **将当日切分为多个时间段**：按交易发生时刻，切为 [昨收 → 交易1 → 交易2 → … → 今收]
   c. **每段用该段持仓 × 该段指数涨跌幅**（涨跌幅用该段起止时刻的分钟 K 线收盘价计算）
   d. 各段 PnL 求和 = 当日总 PnL；逐条快照生成 `trade_log`（含 `reference_price`/`reference_source`）
   e. 当日终态 = 最后一条快照后的仓位
3. NAV *= (1 + 当日总 PnL / 10)
4. 产出每日 NAV 序列 + 各项绩效指标

**参考价格决定 PnL 怎么算**：
- `open`（盘前）→ 交易价格 = 当日开盘价，从开盘到收盘用新仓位
- `intraday`（盘中）→ 交易价格 = 帖子发布时间所在 K 线的收盘价。该日前半段用旧仓位（昨收→交易价），后半段用新仓位（交易价→今收）
- 非交易日/盘后 → 顺延到下一交易日开盘价

**分钟数据不可用时回退**：用日线收盘价做全段计算（从昨收到今收）。

**仓位假设**：
- 仓位快照之间的日期：沿用最近一次公开的仓位（不做日内推测，不猜测博主意图）
- 现金部分不产生收益（无货币基金/逆回购利息）

**加减仓参考价格**（根据帖子发布时间 + 行情数据粒度判定）：

| 条件 | 参考价格 | 逻辑 |
|:---|:---|:---|
| 交易日 + 开盘前（`<9:30`） | 当天**开盘价** | 博主尚未看到当日走势，开盘价是最接近判断时刻的可执行价格 |
| 交易日 + 盘中（`9:30-15:00`） | 帖子发布时间**所在 K 线的收盘价**（分钟级颗粒度优先） | 博主的操作在他看到的 K 线收盘价上执行，粒度越细越接近实际成交价 |
| 交易日 + 收盘后（`>15:00`） | **下一个交易日开盘价** | 当天收盘已发生，博主判断尚未经市场检验 |
| 非交易日（当天无大盘数据） | **下一个交易日开盘价** | 当天无交易，最早可执行时间是下一交易日开盘 |
| 日期已知但具体时间未知 | **下一个交易日开盘价**（保守默认） | 无法判定博主发帖时是否看到当日走势，取最保守假设 |

**盘中 K 线粒度优先级**：

| 优先级 | 数据粒度 | 示例 |
|:---|:---|:---|
| 1（最优） | 1 分钟 K 线 | 帖子 14:23:15 → 所在 1 分钟 K 线是 14:23，取 `close` |
| 2 | 5 分钟 K 线 | 帖子 14:23:15 → 所在 5 分钟 K 线是 14:20~14:25，取 `close` |
| 3（兜底） | 日线收盘价 | 无分钟数据时回退到此 |

## 与方向信号评分的关系

仓位模拟的净值曲线（SIMULATE）和 v11 信号评分（SKILL.md）是两个独立维度：

| | 方向信号评分 (SKILL.md) | 仓位模拟 (SIMULATE.md) |
|:---|:---|:---|
| 适用博主 | 11 位全部适用 | 仅顺应周期（及未来公开仓位的博主） |
| 数据来源 | LLM 标注的 `direction` + `time_horizon` | 帖子中的具体仓位/操作披露 |
| 依赖 | 信号方向 + 窗口价格 | 仓位比例 + 2 指数价格 |
| 回答的问题 | 博主判断方向的能力有多准？ | 博主实际操作赚了多少钱？ |
| 局限 | 无法反映仓位管理（满仓喊多 vs 1成仓喊多，信号无差别） | 仅适用于公开仓位的博主；依赖仓位提取质量 |

两者互补——方向判断好 + 仓位管理好 = 优秀交易者；方向判断好 + 仓位管理差 = 纸上谈兵；方向判断差 + 仓位管理好 = 保守赢家。
