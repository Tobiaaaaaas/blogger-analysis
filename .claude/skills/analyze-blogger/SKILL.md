# 博主分析 Skill（方向预测评估）

LLM 全量读取博主的全部帖子，逐条提取方向预测信号，验证方向对错并按实际收益打分（score = direction × return × 100）。

> **主技能**：本文件 = 方向预测评估（Direction）的规范正式版，原 `Direction.md` 已并入本文件。
> **归档说明**：旧版**拐点线段打分**（v13 dual-contact，return + return2 双触点）已归档至 `archive/skills/analyze-blogger_SKILL_v13_segment.md`，不再作为主技能使用。两者的区别：本技能逐条验证每条帖子中明确的方向预测（方向对了赚 return、错了亏 return）；旧版基于拐点线段做量化打分（return 加权，评估博主在拐点处的判断能力）。两者独立、互补，旧版仅作历史参考。

---

## 用法

```
/analyze-blogger <博主名称> [帖子链接]
```

示例：
```
/analyze-blogger 方向评估 奔走的股票
/analyze-blogger 顺应周期 https://www.toutiao.com/w/1872013328886923/
```

- 提供**帖子链接**：先爬取该作者 2026 年至今的帖子，再进入方向评估
- 提供**博主名称**（帖子已爬取）：直接进入方向评估
- 如未提供参数，Skill 会询问。

- `data/market/market_data.json` 已存在（含 7 指数日线数据，且已更新到最新交易日）
- **DeepSeek API Key**：信号由 DeepSeek 自动提取，key 只通过环境变量传入（**绝不写入文件、绝不提交 GitHub**）：
  - `export DEEPSEEK_API_KEY="sk-..."`（每次运行前设置）
  - 依赖：`pip install openai`

> **行情数据更新**：`python scripts/utils/fetch_market_data.py --start 20240601`（脚本抓取全部 7 指数并与已有数据合并，不会覆盖其他指数）。评估开始前先运行一次，确保验证终点在数据覆盖范围内。
>
> **🕐 爬取范围**：当前只爬 **2026 年至今**的帖子，`python scripts/pipeline/scrape_toutiao.py <链接> --since 2026-01-01`（翻页到早于 since 时自动停止）。信号范围本就只取 2026-01-01+，因此无需覆盖更早年份。

## 评估工作流

### Step 1：加载数据

读入 `data/posts/<博主名>.json` 的全部帖子。之后按需从 `data/market/market_data.json` 中读取与验证日期对应的行情行（无需全量加载，按日期查找即可）。

### Step 2：自动提取信号（DeepSeek）

信号由 `scripts/pipeline/extract_signals_direction.py` 调用 DeepSeek flash 按 §1~§8 规则自动逐条提取（不再人工逐条标注）：

```bash
export DEEPSEEK_API_KEY="sk-..."   # 只经环境变量，绝不写入文件
cd <项目根目录>
python scripts/pipeline/extract_signals_direction.py <博主名>
```

脚本做的事：
1. 读 `data/posts/<博主名>.json` 的帖子（`content` 已含完整正文；若仍有未合并的 `<名>_bodies_s*.json` 正文分片则自动优先读取），过滤 `publish_date >= 2026-01-01`
2. 分批（默认 15 条/批）调 DeepSeek flash，按下方 §1~§8 规则判定并标注 `d`/`s`/`spec`/`idx`/`cat`（JSON schema 见 §3）
3. 脚本强校验：`spec`/`idx` 非法值丢弃、`cat` 归一、同帖重复与同日同周期同方向去重、`summary≤50字`
4. **信号自查**：把「已提取信号 + 原文」回喂 DeepSeek 做独立审查（keep/fix/drop/补加），修掉丢失主结论句（如 07-28 丢了"探底回升我看涨"）、周期误套（结构性无周期误标 scored）、盘前"今天"误判无效-日内等错误
5. 产出 `data/direction_signals/<博主名>.json`，随后运行 `python scripts/eval/run_direction.py <博主名>` 生成报告

> 冒烟测试：`--limit 30` 只处理前 30 条；`--out /tmp/x.json` 写指定路径不动正式数据；`--dry-run` 不调 API；`--no-verify` 跳过自查（更快）。每次运行会覆盖目标文件（无增量续跑）。
>
> **正式入库用 `--runs 3`**：DeepSeek 同 prompt 下每次运行有少量批间随机差异（信号数 ±3 量级）。`--runs 3` 完整跑 3 次（提取+自查），保留 ≥2 次运行都出现的信号后合并，聚合指标（正确率/平均分）跨运行稳定（实测两组独立 3 次共识结果差异在 ±1 个百分点内）。运行元数据写 `data/direction_signals/_<名>_run.json`（gitignored，仅本地溯源）。
>
> **质量边界**：自查能系统性修复"漏结论/周期误套/单列类缺失"等错误（与人工标注精确同键从 63 提升到 ~67），但**不能保证每条语义正确**——方向冲突帖（全文立场与单句结论相反）仍会偶发分歧，且每次运行有少量随机差异。聚合层面（正确率/平均分）与人工标注一致。如需逐条精确可核查，需人工抽检。

## 预测质量逐条打分

**整个过程不能用关键词匹配或正则表达式来筛选或标注。** 每一条帖子的每一个标注字段，都必须由 DeepSeek（通过本脚本）理解帖子语义来判定，而非依赖关键词列表——§1~§8 即写入 DeepSeek system prompt 的标注契约。

脚本自动逐条读帖子，用 DeepSeek 判断每条帖子是否包含方向信号并逐条标注。

**提取为信号的原则**：整条帖子内容中有对上证/大盘/市场的方向上明确的、非模糊的预测。LLM 不应机械地逐项检查，应整体判断：**这篇帖子表达了对大盘未来的明确方向预测吗？** 如果答案是肯定的，就提取信号；如果答案否定的，就不提取。

**可打分性要求**：博主的预测结论必须同时给出**明确的预测周期**（明天/本周/下周等）和**明确的态度**（看涨/看跌、收阳/收阴）。仅仅描述形态（"震荡""筑底""洗盘""蓄势""拉锯""考验X点支撑""探底回升""冲高回落"等）而没有收盘方向态度，无法打分，不提取。

> **默认规则**：帖子中未写明任何指数或板块的名称，默认该帖子是对上证综指/大盘的判断，应提取信号。
>
> **信号时间范围**：只提取 2026 年 1 月 1 日及之后发布的信号。
>
> **参与打分的博主**：帖子最早的时间早于 2026 年（帖子时间范围包含 2026 年 1 月 1 日至今）的博主才参与打分；2026 年才开始发帖的博主不参与打分。**特例**：
> - 枫叶（2026-01-25 开号，比规则迟 25 天且发帖密度高）经指定参与评估
> - 道术合一（2026-02-24 开号）经指定暂时参与打分

### 各博主 LLM 阅读指导

逐条提取前，先按博主的帖子结构特征快速定位核心预测句：

**通用规则**：
- **忽略标题**——标题常是疑问句或引流话术，不代表预测；预测结论在**帖子正文**中寻找
- 在正文中**快速提取方向与预测周期**即可，行情回顾、投资理念、仓位自述不提取
- **注意同一帖子可能出现多信号**（不同周期，如"明天探底回升、下周继续涨"）——按周期分别记多条，各按 §4 规则打分；同一周期重复表述只记一条
- 同一天发布的针对同一周期的相同方向的预测，只记一条（如一天内多帖都喊"明天中阳线"→记一条，保留当天最晚发布的一条）
- 同一天发布的针对不同周期的预测，分开记录
- 同一天发布的针对不同周期的不同方向的预测，分开记录
- 不同日期发布的信号都分开记录

### 1. 信号有效性规则

**信号是否参与打分，取决于预测的时间窗口和发布时间，其中盘中不做日内预测。**

| 发布时间 | 预测对象 | 有效性 | 原因 |
|:---|:---|:---:|:---|
| 交易日盘前（<9:30） | **今天**怎么走 | ✅ 有效 | 参考价=最新收盘价、终点=当天收盘，return 有意义 |
| 交易日盘中/盘后 | **今天**怎么走 | ❌ 无效 | **盘中不做日内预测** |
| 非交易日（周末/假期） | **今天** | ❌ 无效 | 当日无行情可验证，不提取（不标 `spec='today'`） |
| 任何时间 | **明天**/下一个交易日 | ✅ 有效 | 跨日预测，有完整的日线数据可验证 |
| 任何时间 | **下周**/下个月等未来时间 | ✅ 有效 | 未来预测，均可验证 |

> **判断标准**：看预测的**终点**是否有日线收盘价可用。"今天"预测：盘前发布 → 有效（参考价=最新收盘价、终点=当天收盘，return 有意义）；盘中/盘后发布 → 无效——**盘中不做日内预测**；非交易日发布的"今天"预测无当日行情可验证，不提取。

无效信号标注为 `"cat": "无效-日内"`，不参与 §6 的评分体系；但在 §8 汇总表中列出并注明"无效-日内"。

### 3. 信号标注字段

信号写入 `data/direction_signals/<博主名>.json`，schema（引擎 `scripts/eval/run_direction.py` 直接读取）：

```json
{
  "blogger": "博主名",
  "signals": [
    {"pub": "2026-01-04 15:16", "d": 1, "s": 1, "idx": "上证指数",
     "spec": "t1", "summary": "指数开门红的概率大", "cat": "scored"}
  ]
}
```

| JSON 键 | 语义字段 | 取值 |
|:---|:---|:---|
| `pub` | `publish_time` | 帖子发布时间（posts JSON 中对应 `publish_date` 字段，格式 `YYYY-MM-DD HH:MM`，用于判定盘前/盘中/盘后与参考价） |
| `d` | `direction` | `1` = bullish 看多；`-1` = bearish 看空 |
| `s` | `strength` | `2` = strong（措辞坚决："一定""必将""满仓""清仓""坚决""毫无疑问"）；`1` = moderate（有方向判断但措辞温和："偏多""倾向于""大概率""有望"） |
| `idx` | `target_index` | 数据 key 名（默认"上证指数"）；若帖子明确提到某指数/板块则按下方映射表标注对应指数 |
| `spec` | `time_horizon` | 预测周期编码，见 §4 表（`t1`/`t2`/`t3`/`t5`/`tN`/`today`/`week`/`nweek`/`nweek_first`/`month`/`nmonth`/`yearend`/`d:YYYY-MM-DD`）。**精准对应帖子中预测本身的时间周期**，不从宽泛分类中选取——LLM 必须从帖子原文中提取博主明确说的时间，按 §4 规则转换 |
| `summary` | 信号内容摘要 | ≤50 字的预测关键句概括 |
| `cat` | 参与状态 | `scored` = 参与打分（默认）；`无效-日内` / `无预测周期` / `目标点位` = 单列不计分（此类信号的 `spec`/`s` 可省略）。**`待验证` / `无效-过时` 不需要 LLM 手写**：终点超出数据覆盖、或过时（终点 ≤ 参考价日）的信号仍写 `cat="scored"` 且 `spec` 必填，由引擎计算时自动判定并单列 |

> **⚠️ 语义理解原则（关键）**：预测周期必须通过**语义理解**提取——是帖子中对未来的**预测周期**，而不是关键词匹配。帖子中出现"明天"二字不代表这就是对明天市场的预测。例如：
>
> - "明天会怎样，先看4000反击" → ✅ 预测明天 → 预测周期=明天
> - "**明天开始**至本周五，两手准备" → 预测的是**本周** → 预测周期=本周（"明天"只是起止描述）
> - "本人**还剩4成**仓位" → ❌ 仓位自述，不是预测 → 不提取
> - "**接下去**每跌50点加0.5成" → ❌ 仓位计划，不是市场方向预测 → 不提取
> - "**下个目标是4260点**" → ⚠️ **目标点位无时间承诺**——方向明确（bullish），但没有说什么时候到 4260，不能按"几天内"验证 → 归入"目标点位（无时间）"
>
> LLM 必须先回答"这篇帖子预测了什么？"，再回答"这个预测针对什么时间周期？"

**⚠️ 目标点位 vs 时间预测的区分**：博主常用"目标是 X 点""看到 X 点""还有 X 点空间"表述——这些是**目标点位**，只承诺方向，不承诺到达时间。**不能**把目标点位当成"未来几天/下周"预测。除非帖子明确说"X 天内到 4260"（有明确时间 → 按对应预测周期正常打分），否则归入"目标点位（无时间）"：不设验证终点、不参与打分。

### 4. 验证终点

**LLM 必须根据帖子的具体预测周期，确定一个精确的验证日期**，不能泛化到长度区间。

> **"信号日"指帖子发布的自然日**。下表所有"信号日之后第 N 个交易日"均从发布日往后数：周五盘后说"明天涨"→ 明天=周六 → 顺延验证周一；周日说"明天/星期一"→ 验证周一。参考价仍按 §5 定价。

**预测周期 → 验证终点的判定规则**：

| 帖子中的预测周期 | 编码 | 验证终点 |
|:---|:---|:---|
| "今天""今日"（仅盘前发布有效，见 §1） | `today` | 信号日当天收盘 |
| "明天""明日""次日" | `t1` | 信号日之后第 1 个交易日 |
| "后天" | `t2` | 信号日之后第 2 个交易日 |
| "下周""下周一""下周五" | `nweek` / `nweek_first` | 下一周的对应交易日（"下周一"=`nweek_first`=下周第一个交易日；"下周五"=`nweek`=下周最后一个交易日；"下周"未指明星期几 → `nweek`，下周最后一个交易日） |
| "本周""本周内" | `week` | 当周（非交易日发布→下一交易周，见下方说明）的最后一个交易日 |
| "月底前""月末前" | `month` | 当月最后一个交易日 |
| "下个月""下月" | `nmonth` | 下个月的最后一个交易日 |
| "下半年""全年""今年""2026年"等年度预测 | `yearend` | 当年最后一个交易日（数据未覆盖到年底 → 待验证） |
| "N天后""N日内"（N 为具体数字，如"3天后""10天后"） | `tN` | 信号日之后第 N 个交易日（"3天后"→`t3`、"10天后"→`t10`） |
| "1-2天""3-5天"等"X-Y天" | `tY` | 信号日之后第 Y 个交易日（**取预测窗口的最后一个交易日**。博主的原意是"X~Y天内涨"，取第 Y 天验证：如"1-2天"→`t2`、"3-5天"→`t5`） |
| "未来几天" | `t3` | 信号日之后第 3 个交易日（博主未给具体数字，默认 3 天） |
| "近期""短期" 且无具体数字 | `t5` | 信号日之后第 5 个交易日（博主未给具体数字，保守默认） |
| "中长期""未来几个月" | — | **不参与打分**（不设验证终点，备注"无预测周期"，单独统计） |
| **"X月X日""X月X日之前""X月X日前后"（未来具体日期）** | `d:YYYY-MM-DD` | **该日期本身**（若为非交易日则顺延至下一个交易日） |
| **"下周X""周五"等具体星期（未来）** | `d:YYYY-MM-DD` | **对应的具体日期** |
| 完全无预测周期信息 | — | **不参与打分**（不设验证终点，备注"无预测周期"，单独统计） |
| **"目标是X点""看到X点""还有X点空间"（目标点位，无时间承诺）** | — | **不参与打分**（不设验证终点，备注"目标点位-不计时"，单独统计） |

> **⚠️ "近期/短期"硬规则（用户指定）**：预测句中凡出现"近期""短期""很快""马上""即将""不久""临近"且为**向前展望**的表述（如"近期要调整""很快反弹"），一律标 `t5`（信号日之后第 5 个交易日）参与打分；只有纯回顾/状态描述（"已经进入调整阶段""顶背离已经出现"）才归"无预测周期"。

> **目标点位不参与打分**：博主说"目标是 4260"只承诺方向（bullish），没有承诺到达时间。无法确定验证终点，强行设定默认周期验证都会造成误判。此类信号在汇总表中列出并标注"目标点位-不计时"。

> **⚠️ 区分未来日期与回顾日期**：帖子中出现日期不等于预测。必须判断该日期是**对未来的预测窗口**（"8月7日之前都是磨底"→ 预测到 8/7）还是**对过去的回顾**（"2月8日我还提醒了一次"→ 回顾，不提取）。同一日期在预测语境中才标注为具体日期。

> **周末/假期处理**：若预测"明天"但明天是非交易日（周末、节假日），验证终点顺延到**下一个交易日**。例如周五盘后说"明天涨"→ 验证的是周一。此规则通用：**验证终点当日若该指数无行情行（周末、长假、临时休市），一律顺延到下一个有行情行的交易日**。该顺延规则用于 `tN`、`d:` 具体日期类预测；`week`/`nweek`/`nweek_first`/`month`/`nmonth` 类终点本身按交易日历取周期内最后（或首个）交易日——如"下周五"=`nweek`=下周最后一个交易日，若周五休市则取该周最后交易日，不另行顺延。
>
> **非交易日发布的"本周/月底前"**：信号日为周末/假期时，"本周"验证**下一交易周**的最后交易日（引擎行为：基准日顺延到下一交易日所在周）；"月底前"验证发布**自然月**的最后交易日——若发布时当月已无剩余交易日（如月末周末发布"月底前"），该预测已过时，不提取。
>
> **⚠️ 过时预测（通用）**：凡验证终点 ≤ 参考价日的信号一律不提取——典型场景：周五盘后发"本周"（当周已结束）、月末已无剩余交易日发"月底前"、把回顾日期误标为具体日期。引擎侧防御：此类信号自动标注"无效-过时"单列，不计分。

> **核心原则**：博客帖子中预测的时间窗口是什么，就验证那个窗口的终点。说"明天"就只看明天，说"下周"就只看下周——**不扩展、不缩短、不随意假设**。

> **数据覆盖检查**：验证终点必须不晚于 `data/market/market_data.json` 中对应指数的最后一行日期。若终点超出数据覆盖范围，该信号由引擎自动判定为"待验证"（LLM 仍写 `cat="scored"`、`spec` 必填），不参与打分与汇总，在 §8 汇总表中单列。

### 5. 信号参考价

**信号参考价为最新收盘价，与开盘价无关。**

盘中/盘后发布 → 当天收盘价；盘前/非交易日发布 → 上一交易日收盘价（发布时点之前最近一个交易日的收盘价）。

### 6. 打分规则

**score = direction × return**

```
return    = 验证终点收盘价 / 信号参考价 - 1
direction = +1（bullish 看多）
direction = -1（bearish 看空）

score = direction × return × 100
```

**示例**：

| 情形 | 强度 | 参考价 | 终点收盘 | return | direction | 打分 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| 看多，涨了 | moderate | 3800 | 4020 | +5.79% | +1 | **+5.79** |
| 看多，跌了 | **strong** | 3800 | 3760 | -1.05% | +1 | **-1.05** |
| 看空，跌了 | moderate | 4100 | 4072 | -0.68% | -1 | **+0.68** |
| 看空，涨了 | **strong** | 4100 | 4120 | +0.49% | -1 | **-0.49** |

### 7. 汇总指标

对博主的所有预测信号汇总（**只统计参与打分的有效信号**；无效/目标点位/无预测周期/待验证信号单列，不计入任何指标）：

```
信号总数：N
  另有：无效-日内 X 条 / 无预测周期 X 条 / 目标点位-不计时 X 条 / 无效-过时 X 条 / 待验证 X 条（单列，不计分）
方向正确：N（正确率 N% = score>0 的信号数 / (N − 平数)；score=0 计"平" X 条，平数不计入分子分母）
  - strong 正确：N/N（正确率 N%）
  - moderate 正确：N/N（正确率 N%）
平均分：+X.XX（= 单信号平均收益 %，核心指标）
波动率：X.XX（单信号 score 样本标准差，n-1 分母）
夏普：+X.XX（= 平均分 / 波动率；信号 <2 条或波动率为 0 时显示 —）
最大回撤：-X.XX（按信号发布时间顺序累加单信号 score 的曲线峰值回撤）
最高分：+X.XX / 最低分：-X.XX
看多平均分：+X.XX（N 条）  看空平均分：+X.XX（N 条）
```

### 8. 汇总表格

```
| # | 日期 | 内容(≤50字) | 方向 | 强度 | 预测周期 | 目标指数 | 参考价 | 终点日 | 终点收盘 | return | 分 | 备注 |
|:---|:---|:---|:---|:---|:---|:---|:---:|:---:|:---:|:---:|:---:|:---|
| 1 | 01-07 | 上攻已显疲态，将进入回调 | ↓ | mod | 明天 | 上证 | 4083 | 01-08 | 4072 | -0.27% | +0.27 | — |
| 2 | 01-09 | 明天A股绝地反击 | ↑ | str | 明天 | 上证 | 4120 | 01-12 | 4165 | +1.09% | +1.09 | — |
| ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |
```

> **备注列**：正常信号填 `—`；无效信号填 `无效-日内`（盘中/盘后"今天"）；目标点位填 `目标点位-不计时`；完全无预测周期信息填 `无预测周期`（含"未来一段时间""中长期"等模糊周期）；验证终点超出数据范围填 `待验证`；验证终点 ≤ 参考价日（过时预测）填 `无效-过时`（`待验证`/`无效-过时` 均由引擎自动判定）。无效/目标点位/无预测周期/无效-过时/待验证信号不参与打分与 §7 汇总。方向正确 = 验证终点收盘优于参考价（score>0），验证重点在终点。

`reports/<博主名称>_direction.md` 的格式（引擎自动生成）：

- **三个分类表**（每表均含 信号数 / 平均分 / 胜率）：
  1. 按预测指数分类（上证指数/上证50/科创50/创业板指/双创等）
  2. 按看多/看空分类（含 strong/moderate 子行）

  - ⚠️ **覆盖不足**：覆盖 < 3 个月（样本期过短，排名参考价值低）
  - ⚠️ **高度集中**：单月占比 ≥ 50%；**轻度集中提示**：单月占比 33%~50%
  - ⚠️ **严重覆盖缺口**：相邻月份之间缺 ≥ 3 个月；缺 1-2 个月给提示
  - 典型场景：博主停更/减产（帖子数据完整但信号稀疏）、帖子数据缺失（需回查 posts 文件）、标注未完成（如枫叶 4-8 月待补标注）
- **逐条汇总表**：按 §8 的列结构输出全部信号
- **观察要点**：正确率结论、多空对比、最强/最弱预测周期与指数、最大单条命中/失误、单列信号统计

**横向对比**：`python scripts/eval/comparison_all.py` 生成 `reports/comparison_direction.md`，包含：
- **总榜**（按平均分排序，附计分信号数/正确率/**波动率/夏普/最大回撤**/多空数）——**排名资格：计分信号 ≥ 30 条**，不足者不参与排名、单列注明（统计无意义）
- 按预测周期分类的**三档归类**（**交易日**，信号日→验证终点的交易日数量：0-1个交易日（今天/明天）、2-5个交易日（1周内）、6个交易日及以上（大于1周）；其中"今天（盘前）"在 0-1 档下单列子行，群体最强共性档）——**各档排名资格：该档信号 ≥ 10 条**
- 按看多看空分类、按预测指数分类、按月份分类
- **信号覆盖/集中度警告**（同上述阈值，逐博主列出）

**预测周期三档归类的详细算法**：

```
输入：信号的发布日 pub_date、验证终点 ep（§4 规则算出）
交易日历 CAL = market_data.json 中"上证指数"的日期序列（升序）

1. 基准日 base = pub_date 若 pub_date ∈ CAL；否则 base = CAL 中 pub_date 之前最近的一个交易日
2. 跨度 span = CAL.index(ep) − CAL.index(base)     # 信号日→验证终点的交易日数量
3. 分档：
     span ≤ 1  → 0-1个交易日（今天/明天）
     2 ≤ span ≤ 5 → 2-5个交易日（1周内）
     span ≥ 6  → 6个交易日及以上（大于1周）
4. 子行：spec == today 的信号，在 0-1 档下方单列一行"其中：今天（盘前）"

边界示例：
  - 周五发布"明天"→ ep=下周一，span=1 → 0-1 档
  - 周一发布"下周初"→ ep=下周一，span=5 → 2-5 档
  - 周一发布"下周"→ ep=下周五，span=9 → 6+ 档
  - 周六发布"明天"→ base=周五，ep=下周一，span=1 → 0-1 档
```

> 实现位置：`scripts/eval/comparison_all.py` 的 `bucket_of()` 函数，与引擎 `run_direction.py` 共用同一交易日历与 prev_td 逻辑。

## 注意事项

- **只验证、不预测**——你的任务是评估博主的过去预测准确率，不是对未来走势发表观点
- **严格按预测周期验证**——帖子说"明天"就只看明天，不扩展到 3 天
- **打分即收益**——方向对了赚 return、错了亏 return
- **诚实打分**——博主预测准确率低就说低，不要粉饰
- **代码与文档一致性**：本文件 §1~§8 与 `run_direction.py` 一一对应；若修改任一规则，需同步另一方（引擎自测：`python scripts/eval/run_direction.py --selftest`）
