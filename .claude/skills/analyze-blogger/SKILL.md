# 博主分析 Skill

分析财经博主的大盘预测能力。默认平台为今日头条，核心关注拐点判断和拐点之间趋势判断。

> 大盘 = 市场 = 上证 = 上证综指。全文等价。复述 SKILL 中"大盘方向判断"即指上证综指择时。

## 用法

```
/analyze-blogger <博主名称> <帖子链接>
```

示例：
```
/analyze-blogger 顺应周期 https://www.toutiao.com/w/1872013328886923/
```

如未提供参数，Skill 会询问。

## 工作流

### Step 1: 爬取帖子

```bash
cd <项目根目录> && python scripts/scrape_toutiao.py <帖子链接>
```

- 从帖子链接自动提取 token 和用户主页，翻页获取全部帖子
- **覆盖时间与大盘分析对齐**：需获取从 2024 年 6 月至今的所有帖子
- 爬虫 target 已设为 5000，确保不遗漏早期帖子
- 输出到 `data/posts/<博主名>.json`（通过 `--name <博主名>` 参数指定）

如果帖子已爬取且覆盖到 2024 年 6 月，可以跳过此步。

### Step 1.5: LLM 信号提取

> **v10 变更**：全量读取帖子，LLM 逐条标注信号。不再分片、不再正则匹配。

**整个过程不能用关键词匹配或正则表达式来筛选或标注。** 每一条帖子的每一个标注字段 (direction/strength/time_horizon)，都必须由 LLM 通过理解帖子语义来判定，而非依赖关键词列表。

一次性读完全部帖子，用 LLM 判断每条帖子是否包含方向信号并逐条标注。

**提取为信号**的原则：整条帖子内容中有对上证/大盘/市场的方向上明确的、非模糊的预测。LLM 不应机械地逐项检查，应整体判断：**这篇帖子表达了对大盘未来的明确方向预测吗？** 如果答案是肯定的，就提取信号；如果答案否定的，就不提取。

> **默认规则**：帖子中未写明任何指数或板块的名称，默认该帖子是对上证综指/大盘的判断，应提取信号。
>
> **发布日期未知**：如果帖子的发布日期无法确定，则不提取为信号。

**信号标注字段**：LLM 必须通过理解帖子的完整语义来判断并标注，不能依赖关键词匹配。

- `direction`: bullish / bearish
- `strength`: strong / moderate
  - `strong` — 措辞坚决（"一定""必将""满仓""清仓""坚决"）+ 给出具体点位/仓位
  - `moderate` — 有方向判断但措辞温和（"偏多""倾向于""大概率""有望"）
- `time_horizon`: short / medium / long / unspecified
  - `short` — 3天内预测（T ~ T+2，"明天涨""下午反弹"，包括日内）
  - `medium` — 预测周期 T+3 到 1 个月，更关注 1-2 周（"下周""月中""月底前"）
  - `long` — 预测周期 1 个月及以上（"下个月""下半年""牛市""明年"）
  - `unspecified` — 无明确时间范围

> **time_horizon 标注原理**：LLM 必须通过理解帖子的完整语义来判断时间维度，**不能依赖关键词匹配**。LLM 必须理解整个帖子的信号针对的预判周期，不能按照一句话以偏概全。当帖子同时包含不同级别的时间信息时，以信号针对的预判周期来标注该帖子的 time_horizon。
- `evidence`: 帖子原文（关键句，≤300字）
- `publish_time`: 帖子发布时间（YYYY-MM-DD HH:MM 格式），用于判定参考价格

### Step 4: 对照分析（核心）

**你必须自己完成分析，不依赖任何规则脚本。**

#### 4.1 对照拐点

对 `market_analysis.md` 中的每个 **Major 拐点**（M1-M8）：
- 找到博主在拐点前后的帖子
- 对照博主的判断与市场实际走势
- 应用下面的 4 条评估原则
- 对 **Intermediate 拐点**（I1-I15）选择性分析，只分析博主有明确表态的

#### 4.2 按以下 4 条原则逐拐点评判

**原则 1：拐点参考知识库，不再自行判断**
市场拐点已由 `market_analysis.md` 给出。你的任务是**对照博主的判断和知识库中的拐点**，而非重新发现拐点。

**原则 2：最终标准——跟随操作会不会有重大损失**
这比准确率更重要。追问：如果按照博主的建议操作，会不会在顶部追高被深套？会不会在底部割肉？会不会错过大的波段行情？好的博主不一定每次都对，但他的框架能在看错时保护跟随者。

**原则 3：抄底/逃顶分离——同一个人"什么时候买"和"什么时候卖"是两种独立能力**
评估时必须将抄底和逃顶作为两个独立维度分别评分，不可合成"综合评估"。跟随者需要知道：**这个博主告诉我"什么时候买"靠谱，还是告诉我"什么时候卖"靠谱？**

**原则 4：信号打分核心逻辑：**
每条信号独立评分，不依赖线段方向或拐点接近度。score = direction_sign × return × strength_base。详见 §4.3.3。

#### 4.3 拐点线段评估（打分制）

##### 4.3.1 线段模型

市场拐点由 `market_analysis.md` 定义（M1-M8 + I1-I15）。相邻拐点之间形成**线段**，方向由两端拐点类型决定：

- **上升段**：从底部拐点到下一个顶部拐点
- **下降段**：从顶部拐点到下一个底部拐点

##### 4.3.2 信号参考价格（定价规则）

**信号参考价格**（根据帖子发布时间和大盘数据判定）：

- 当天**有大盘数据**（交易日）：
  - 开盘前（<9:30）→ 使用**当天开盘价**（判断未经市场检验）
  - 盘中（9:30-15:00）→ 使用**当天收盘价**（博主看到了当天走势，收盘价反映当日结果）
  - 收盘后（>15:00）→ 使用**下一个交易日开盘价**（当天收盘已发生，判断尚未经检验）
- 当天**无大盘数据**（非交易日）→ 使用**下一个交易日开盘价**
- 发布日期已知但具体时间未知 → 默认使用下一个交易日开盘价

> **T 日**即参考价对应的交易日：
> - 信号在开盘前/盘中发出 → T 日 = 信号日（参考价 = 当日开盘/收盘）
> - 信号在收盘后/非交易日发出 → T 日 = 下一个交易日（参考价 = 下一日开盘）
> - 时间未知 → T 日 = 下一交易日

##### 4.3.3 return 因子与打分规则

**return 因子**：根据信号的 `time_horizon` 确定采样窗口，计算其平均收盘价相对于信号参考价的变动百分比。

```
return = avg_close(window) / P_ref - 1
```

`window` 由 `time_horizon` 决定（`T` 为参考价对应的交易日，见 §4.3.2）：

| time_horizon | 窗口 | 含义 |
|:---|:---|:---|
| short | T, T+1, T+2 | 3 个交易日内 |
| medium | T+5 ~ T+10 | 约 1-2 周后的 6 个交易日 |
| long | T+20, T+21, T+22 | 1 月后的 3 个交易日 |
| unspecified | T+20, T+21, T+22 | 无明确时间范围，按月度窗口评估 |

> 例：信号 time_horizon = short，T = 5/16（周一）。window = [5/16(周一), 5/17(周二), 5/18(周三)]。
> avg = (4010+4020+3980)/3 = 4003，ref = 4000，return = 4003/4000 - 1 = +0.08%。

**打分公式**：

```
direction_sign = +1 (bullish) / -1 (bearish)
strength_base = 2 (strong) / 1 (moderate)
score = direction_sign × return × strength_base
```

> 注：分数以百分比表示（return 和 score 均已 ×100）。

**公式的自然含义**：
- bullish + 均价涨了 → 正分（看多对了）
- bullish + 均价跌了 → 负分（看多错了）
- bearish + 均价跌了 → 正分（看空对了）
- bearish + 均价涨了 → 负分（看空错了）

##### 4.3.4 共 14 个分数（7 个总得分 + 7 个平均分）

**总得分：**

```
① 综合总得分 = 所有信号的 score 之和（score=0 的信号不参与）
② 上升段总得分 = 所有上升段内信号的 score 之和（线段方向由 zigzag 事后确定，仅用于统计分组）
③ 下降段总得分 = 所有下降段内信号的 score 之和
④ 抄底总得分 = 底部拐点 ±1天（共三个交易日）内信号的 score 之和
⑤ 逃顶总得分 = 顶部拐点 ±1天（共三个交易日）内信号的 score 之和
⑥ 看多总得分 = 所有 bullish 信号的 score 之和
⑦ 看空总得分 = 所有 bearish 信号的 score 之和
```

**单信号平均分（百分比）：**

```
⑧ 综合平均分 = (① / 有效信号数)
⑨ 上升段平均分 = (② / 上升段有效信号数)
⑩ 下降段平均分 = (③ / 下降段有效信号数)
⑪ 抄底平均分 = (④ / 抄底有效信号数)
⑫ 逃顶平均分 = (⑤ / 逃顶有效信号数)
⑬ 看多平均分 = (⑥ / bullish 有效信号数)
⑭ 看空平均分 = (⑦ / bearish 有效信号数)
```

> 所有 time_horizon 均参与评分。仅当窗口交易日数据不足时 score = 0。

拐点类型判定：
- **底部拐点**：M1(2690)、M3(3041)、M5(3795)、M8(3741)、I1(3153)、I3(3227)、I5(3141)、I9(3816)、I11(4003)、I13(3928)
- **顶部拐点**：M2(3674)、M4(4034)、M6(4259)、M7(4380)、I2(3510)、I4(3495)、I6(3439)、I10(4191)、I12(4197)、I14(4175)
（I7、I8、I15 非上证拐点，视 market_analysis.md 的具体定义判定）

> 注：线段方向（上升/下降）和拐点归属（抄底/逃顶）均由 zigzag 事后确定，**不参与打分公式**，仅用于统计分组——回答"博主在什么市场环境中表现更好"。

##### 4.3.6 定性分析注意事项

除了量化分数，LLM 定性分析时还需关注博主在每条线段内的**态度一致性**：

- **持续看多/看空**：博主在整个线段中方向始终如一。如果对了→信念坚定有远见；如果错了→顽固不化
- **摇摆不定**：博主在线段内一会儿多一会儿空（如 M6→I13 段的大盘蜂向标：先空转多再转空）。这种"多空反复横跳"本身就是负面信号——连方向都拿不准的博主不可跟
- **一次性表态**：博主只在拐点附近表态一次，随后沉默。表态对了→有远见；表态错了→一次失误

报告中须以线段为单位总结博主的态度模式，比如"该线段中博主持续看多 17 条，态度一致但方向错了"或"该线段中博主在 5/27 由空转多，之后连续喊多 12 条直至线段结束"。

#### 4.4 评估流程总结

评估流程分两步：

1. **拐点线段评估（§4.3）**：所有信号按 time_horizon 对应窗口打分，产出 14 个分数（7 总得分 + 7 平均分）+ 按 time_horizon 分组得分
2. **LLM 定性分析（§4.1-4.2）**：对照拐点逐条分析博主的代表性判断，引用原文，给出 nuanced 评价

互相验证：线段打分提供量化框架，LLM 定性提供深度解读。如有矛盾（如分数高但 LLM 发现博主只是喊口号），以 LLM 定性为准并解释原因。

## 注意事项

- **只分析、不预测**：你的任务是评估博主的过去表现，不是对未来走势发表观点
- **不要刻板打分**：避免"60%准确率"这类机械统计，用 14 个分数 + time_horizon 分组 + nuanced 定性评价
- **引用原文**：关键判断要引用博主的原话，让读者自己判断
- **保持诚实**：博主没有判断的拐点就说没有，不要强行找预测
- **注意时期背景**：牛市中的看多和熊市中的看多，含金量完全不同
- **分数解释要谨慎**：高分不一定代表能力强（可能只是顺势躺赢），低分不一定代表差。重要的是博主在拐点处的表现
- **互相比对验证**：线段打分提供量化框架，LLM 定性提供深度解读。如有矛盾，以 LLM 定性为准并解释原因
