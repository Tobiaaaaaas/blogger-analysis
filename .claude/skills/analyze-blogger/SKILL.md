# 博主分析 Skill

分析财经博主的大盘预测能力。默认平台为今日头条，核心关注大级别拐点判断而非日间波动。

## 用法

```
/analyze-blogger <博主名称> <帖子链接>
```

示例：
```
/analyze-blogger 顺应周期 https://www.toutiao.com/w/1872013328886923/
```

如未提供参数，Skill 会询问。

## 工作流

### Step 1: 爬取帖子

```bash
cd <项目根目录> && python scripts/scrape_toutiao.py <帖子链接>
```

- 从帖子链接自动提取 token 和用户主页，翻页获取全部帖子
- **覆盖时间与大盘分析对齐**：需获取从 2024 年 6 月至今的所有帖子
- 爬虫 target 已设为 3000，确保不遗漏早期帖子
- 输出到 `data/posts/posts.json`

如果帖子已爬取且覆盖到 2024 年 6 月，可以跳过此步。

### Step 1.5: 帖子初筛（关键词匹配）

```bash
cd <项目根目录> && python scripts/filter_posts.py
```

爬取的原始帖子包含大量噪音（纯描述、自我宣传、个股推荐、新闻转述）。用**关键词匹配**快速筛选，只保留有方向判断或操作建议的帖子。

**保留**：帖子包含方向判断关键词（如：看涨、看跌、见顶、见底、突破、反弹、反转、拐点、牛市、熊市...）或操作建议关键词（如：买入、卖出、加仓、减仓、高抛、低吸、抄底、逃顶...）。

**丢弃**：不含任何上述关键词的帖子。

输出到 `data/posts_filtered.json`。

### Step 2: 获取市场数据

```bash
cd <项目根目录> && python scripts/fetch_market_data.py
```

- 获取上证指数、沪深300、创业板指日线数据
- 默认覆盖当年全年 + 前后缓冲
- 输出到 `data/market_data.json`

如果已有当天数据，可以跳过。

### Step 3: 加载先验知识

**必须先阅读 `knowledge/market_analysis.md`** — 这是已验证的大盘拐点知识库，包含：

- 2024.06 ~ 2026.07 完整走势，分为 5 个阶段（探底→政策牛→震荡→主升→调整）
- **8 个 Major 拐点**（M1-M8）：2690大底、3674脉冲顶、3041关税底、4034首次触4000、3795急跌底、4259上证年度顶、4380创业板年度顶、3741当前调整底
- **15 个 Intermediate 拐点**（I1-I15）：阶段内的中级别波动
- 三指数（上证/沪深300/创业板）zigzag 拐点链 + 月度速查表 + 风格分化分析

**不需要重新识别市场拐点**。所有拐点已在 market_analysis.md 中标明并分级，直接引用。

### Step 4: 对照分析（核心）

**你必须自己完成分析，不依赖任何规则脚本。**

#### 4.1 对照拐点

对 `market_analysis.md` 中的每个 **Major 拐点**（M1-M9）：
- 找到博主在拐点前后的帖子
- 对照博主的判断与市场实际走势
- 应用下面的 8 条评估原则
- 对 **Intermediate 拐点**（I1-I7）选择性分析，只分析博主有明确表态的

#### 4.2 按以下 8 条原则逐拐点评判

**原则 1：拐点参考知识库，不再自行判断**
市场拐点已由 `market_analysis.md` 给出。你的任务是**对照博主的判断和知识库中的拐点**，而非重新发现拐点。

**原则 2：只看大节点，忽略日间噪音**
日内/次日的涨跌判断不计入核心评估。真正有价值的是博主在阶段顶部、底部、趋势反转处的判断。

**原则 3：方向性失误才是真正扣分项——且"被套"远重于"卖飞"**

不是所有的"错"都同等。按严重程度排序：

- **最严重：让跟随者被套** — 顶部喊继续突破、底部喊还要暴跌，导致跟随者追高被深套或恐慌割肉在底部。这种错误可能造成致命损失。
- **较轻：让跟随者卖飞** — 过早判断顶部导致提前离场，错过了后续涨幅。跟随者少赚了但没有亏损。这种"错"远不如被套严重。
- **不扣分**："看涨但涨得不够多"、"时间早了两周"这类节奏偏差。

**核心原则：宁可卖飞，不可被套。** 评估时区分"博主让你亏钱了"和"博主让你少赚了"——前者是真正的 red flag。

**原则 4：条件性预测要识别框架质量**
"如果破 4180 则看 3600"——这是有框架的判断，不是模糊。即使条件未触发，框架本身的价值也应被认可。

**原则 5：及时性——超过一周的观点没有太大意义**

- **高价值**：拐点**当天**的判断——"今天这里是顶"、"这个位置可以加仓"。跟随者能立即行动。
- **中等价值**：1-3 天内的短线判断——"明天看反弹"、"本周调整为主"。
- **低价值**：超过一周的预判——"月底前后有反弹窗口"、"7月底8月初见底"。方向可能对，但时间窗口太宽，跟随者无法精确操作。
- **无实操价值**：月度以上的远期展望——"今年高点 4250"、"大底在 3600"。即使兑现，也只是一个数字，不构成操作依据。

评估时追问：**如果我是博主当时的读者，看到这条帖子，我今天或明天能据此做出买卖决策吗？** 如果不能，就不是高价值判断。

**原则 6：时效性标注**
注意帖子发布时间点：开盘前/盘中/收盘后？这直接影响判断的含金量。盘中跟随走势做出的判断含金量低于盘前独立预判。

**原则 7：越明确越有分量**
模糊的"可能涨也可能跌"没有评估价值。给出了具体点位、明确仓位建议（如"在3960加1成"）、清晰板块方向的观点，无论对错都是有价值的——对了说明能力强，错了也能验证其框架是否靠谱。明确性本身就是一种敢于负责的态度。

**原则 8：最终标准——跟随操作会不会有重大损失**
这比准确率更重要。追问：如果按照博主的建议操作，会不会在顶部追高被深套？会不会在底部割肉？会不会错过大的波段行情？好的博主不一定每次都对，但他的框架能在看错时保护跟随者。

#### 4.3 上证拐点覆盖：召回率 / 精确率（LLM 定性为主）

对照 `market_analysis.md` 中与博主发帖期重叠的所有上证拐点（Major + Intermediate），逐一判断：

**召回率**：博主对这些拐点有多少给出了明确判断？
- "有明确观点" = 给出了方向、点位或操作建议
- "无明确观点" = 拐点处帖子在说别的，或只有模糊描述
- 追问：博主有没有**漏掉**重要的拐点？

**精确率**：博主给出明确判断的那些拐点，判断对了吗？
- "方向正确" = 看涨后涨、看跌后跌
- "方向错误" = 看涨后跌、看跌后涨（原则 3 的重大失误）
- "部分正确" = 方向对但节奏/幅度有偏差

**重要**：数字仅作辅助参考框架，不替代 LLM 的 nuanced 判断。不要算出"75.3%"这种数字——用"大部分拐点都覆盖了，但 M7 漏了"这种表述。

### Step 4.5: 信号精确率验证（事件研究法）

拐点分析回答了"博主有没有抓住大拐点"（召回率），这一步回答"博主的每次方向判断在后续市场中是对是错"（精确率）。两者互补。

#### 4.5.1 提取方向性信号

对照 Step 4 的拐点分析结果，提取博主每次**明确方向性判断**作为信号事件，写入 `data/signals/<博主名>.json`：

```json
{
  "blogger": "<博主名>",
  "signals": [
    {
      "date": "YYYY-MM-DD",
      "direction": "bullish | bearish",
      "strength": "strong | moderate",
      "specific": "explicit_action | directional_clear | directional_vague",
      "evidence": "博主原话摘要",
      "index": "上证指数 | 创业板指"
    }
  ]
}
```

**提取规则**：
- 拐点处有明确判断 → 提取为信号
- 博主在非拐点时期有明确看多/看空表态 → 也提取
- 模糊表态不算信号（"可能涨也可能跌"之类）
- 每天重复同一立场只记首次，立场**转变**时才记新信号
- `strength`：给出具体操作建议+仓位比例 = strong，仅方向判断 = moderate

#### 4.5.2 运行验证脚本

```bash
cd <项目根目录> && python scripts/evaluate_precision.py --blogger <博主名>
```

脚本对每个信号，查 `data/market_data.json` 计算 T+1/3/5/10/20 个交易日后的指数涨跌：
- bullish 信号：后续涨了 → 正值（判断正确），跌了 → 负值（错误）
- bearish 信号：后续跌了 → 正值（判断正确），涨了 → 负值（错误）

#### 4.5.3 将结果写入报告

运行结果填入报告的 `📊 信号精确率验证` 章节。

## 注意事项

- **只分析、不预测**：你的任务是评估博主的过去表现，不是对未来走势发表观点
- **不要刻板打分**：避免"60%准确率"这类机械统计，给出 nuanced 的定性评价
- **引用原文**：关键判断要引用博主的原话，让读者自己判断
- **保持诚实**：博主没有判断的拐点就说没有，不要强行找预测
- **注意时期背景**：牛市中的看多和熊市中的看多，含金量完全不同
- **双轨互相验证**：拐点分析说"逃顶强"，精确率验证应该 confirmation；如果有矛盾，深挖原因
