# 博主分析 Skill

分析财经博主的大盘预测能力。默认平台为今日头条，核心关注大级别拐点判断而非日间波动。

## 用法

```
/analyze-blogger <博主名称> <帖子链接>
```

示例：
```
/analyze-blogger 顺应周期 https://www.toutiao.com/w/1872013328886923/
```

如未提供参数，Skill 会询问。

## 工作流

### Step 1: 爬取帖子

```bash
cd <项目根目录> && python scripts/scrape_toutiao.py <帖子链接>
```

- 从帖子链接自动提取 token 和用户主页，翻页获取全部帖子
- **覆盖时间与大盘分析对齐**：需获取从 2024 年 6 月至今的所有帖子
- 爬虫 target 已设为 3000，确保不遗漏早期帖子
- 输出到 `data/posts/posts.json`

如果帖子已爬取且覆盖到 2024 年 6 月，可以跳过此步。

### Step 1.5: 帖子初筛（关键词匹配）

```bash
cd <项目根目录> && python scripts/filter_posts.py
```

爬取的原始帖子包含大量噪音（纯描述、自我宣传、个股推荐、新闻转述）。用**关键词匹配**快速筛选，只保留有方向判断或操作建议的帖子。

**保留**：帖子包含方向判断关键词（如：看涨、看跌、见顶、见底、突破、反弹、反转、拐点、牛市、熊市...）或操作建议关键词（如：买入、卖出、加仓、减仓、高抛、低吸、抄底、逃顶...）。

**丢弃**：不含任何上述关键词的帖子。

输出到 `data/posts_filtered.json`。

### Step 2: 获取市场数据

```bash
cd <项目根目录> && python scripts/fetch_market_data.py
```

- 获取上证指数、沪深300、创业板指日线数据
- 默认覆盖当年全年 + 前后缓冲
- 输出到 `data/market_data.json`

如果已有当天数据，可以跳过。

### Step 3: 加载先验知识

**必须先阅读 `knowledge/market_analysis.md`** — 这是已验证的大盘拐点知识库，包含：

- 2024.06 ~ 2026.07 完整走势，分为 5 个阶段（探底→政策牛→震荡→主升→调整）
- **8 个 Major 拐点**（M1-M8）：2690大底、3674脉冲顶、3041关税底、4034首次触4000、3795急跌底、4259上证年度顶、4380创业板年度顶、3741当前调整底
- **15 个 Intermediate 拐点**（I1-I15）：阶段内的中级别波动
- 三指数（上证/沪深300/创业板）zigzag 拐点链 + 月度速查表 + 风格分化分析

**不需要重新识别市场拐点**。所有拐点已在 market_analysis.md 中标明并分级，直接引用。

### Step 4: 对照分析（核心）

**你必须自己完成分析，不依赖任何规则脚本。**

#### 4.1 对照拐点

对 `market_analysis.md` 中的每个 **Major 拐点**（M1-M9）：
- 找到博主在拐点前后的帖子
- 对照博主的判断与市场实际走势
- 应用下面的 8 条评估原则
- 对 **Intermediate 拐点**（I1-I7）选择性分析，只分析博主有明确表态的

#### 4.2 按以下 8 条原则逐拐点评判

**原则 1：拐点参考知识库，不再自行判断**
市场拐点已由 `market_analysis.md` 给出。你的任务是**对照博主的判断和知识库中的拐点**，而非重新发现拐点。

**原则 2：只看大节点，忽略日间噪音**
日内/次日的涨跌判断不计入核心评估。真正有价值的是博主在阶段顶部、底部、趋势反转处的判断。

**原则 3：方向性失误由不利波动幅度决定，不由事后拐点标签决定**
拐点是事后才知道的。评估博主的某个判断时，不能用"这个位置后来证明是顶/底"来给失误加权——这在当时信息下是不可能知道的。失误的严重程度只有一个标准：**跟随操作后的不利波动幅度**。看多信号跌了 10% 就是比跌了 2% 严重，和这个位置后来有没有被称为"拐点"无关。

**原则 4：条件性预测要识别框架质量**
"如果破 4180 则看 3600"——这是有框架的判断，不是模糊。即使条件未触发，框架本身的价值也应被认可。

**原则 5：及时性——超过一周的观点没有太大意义**

- **高价值**：拐点**当天**的判断——"今天这里是顶"、"这个位置可以加仓"。跟随者能立即行动。
- **中等价值**：1-3 天内的短线判断——"明天看反弹"、"本周调整为主"。
- **低价值**：超过一周的预判——"月底前后有反弹窗口"、"7月底8月初见底"。方向可能对，但时间窗口太宽，跟随者无法精确操作。
- **无实操价值**：月度以上的远期展望——"今年高点 4250"、"大底在 3600"。即使兑现，也只是一个数字，不构成操作依据。

评估时追问：**如果我是博主当时的读者，看到这条帖子，我今天或明天能据此做出买卖决策吗？** 如果不能，就不是高价值判断。

**原则 6：时效性标注**
注意帖子发布时间点：开盘前/盘中/收盘后？这直接影响判断的含金量。盘中跟随走势做出的判断含金量低于盘前独立预判。

**原则 7：越明确越有分量**
模糊的"可能涨也可能跌"没有评估价值。给出了具体点位、明确仓位建议（如"在3960加1成"）、清晰板块方向的观点，无论对错都是有价值的——对了说明能力强，错了也能验证其框架是否靠谱。明确性本身就是一种敢于负责的态度。

**原则 8：最终标准——跟随操作会不会有重大损失**
这比准确率更重要。追问：如果按照博主的建议操作，会不会在顶部追高被深套？会不会在底部割肉？会不会错过大的波段行情？好的博主不一定每次都对，但他的框架能在看错时保护跟随者。

**原则 9：信号频率是风格特征，不是过滤理由**
拐点是事后才知道的，博主事前无法判断"这里是不是拐点"。因此**所有 strong + 明确方向的信号都应假设跟随操作并评估质量**，不按是否在拐点附近筛选。

但信号频率是重要的博主风格特征：高频信号（如每天喊方向）的胜率自带市场惩罚——在无趋势的日常波动中频繁做方向判断，准确率自然低于只在关键节点表态的博主。报告中将信号频率作为博主特征标注，而非过滤条件。

**原则 10：看多/看空分离——同一个人抄底和逃顶能力不可混评**
一个博主在顶部看空极准（如稀豹看空胜率 70%），不代表他在底部看多也可靠（看多仅 37.5%）。评估时必须将看多（抄底）和看空（逃顶）作为两个独立维度分别评分。跟随者需要知道：**这个博主告诉我"什么时候买"靠谱，还是告诉我"什么时候卖"靠谱？**

**原则 11（v7 新增）：信号的时间维度决定评估窗口**
不是所有信号都应该用同一套时间窗口评估。一个"明天看涨"的短线判断在 T+20 已经过了有效期，不应该用 T+20 来评判对错；一个"牛市下半场即将开启"的长线判断在 T+5 趋势还没展开，也不应该用 T+5 来判负。v7 对每条信号标注时间维度（intraday/short/medium/long），用加权综合评分代替单一窗口排名：
- 短线信号（intraday/short）主要用 T+5/T+10 评估，T+20 权重为 0
- 中线信号（medium）均衡评估 T+5~T+20
- 长线信号（long）主要用 T+15/T+20 评估，额外评估 T+40/T+60
- 未指定信号采用均衡权重

报告结论应优先参考**时间加权综合胜率**，而非单一 T+20 窗口。同时标注博主的最优窗口和衰减模式。

#### 4.3 上证拐点覆盖：召回率 / 精确率（LLM 定性为主）

对照 `market_analysis.md` 中与博主发帖期重叠的所有上证拐点（Major + Intermediate），逐一判断：

**召回率**：博主对这些拐点有多少给出了明确判断？
- "有明确观点" = 给出了方向、点位或操作建议
- "无明确观点" = 拐点处帖子在说别的，或只有模糊描述
- 追问：博主有没有**漏掉**重要的拐点？

**精确率**：博主给出明确判断的那些拐点，判断对了吗？
- "方向正确" = 看涨后涨、看跌后跌
- "方向错误" = 看涨后跌、看跌后涨（原则 3 的重大失误）
- "部分正确" = 方向对但节奏/幅度有偏差

**重要**：数字仅作辅助参考框架，不替代 LLM 的 nuanced 判断。不要算出"75.3%"这种数字——用"大部分拐点都覆盖了，但 M7 漏了"这种表述。

### Step 4.5: 信号精确率验证（看多/看空分离定量评估）

拐点分析回答"博主有没有抓住大拐点"（召回率），这一步回答两个独立问题：
- **看多/抄底能力**：博主喊买入后，市场表现如何？买入后的最大回撤是多少？
- **看空/逃顶能力**：博主喊卖出后，市场表现如何？卖出后的最大踏空是多少？

**重要：看多和看空分开评估，不混在一起。**

#### 4.5.1 提取方向性信号

**核心原则：提取所有有预测意图的方向性帖子。描述性语言（有方向词但无预测意图）应被排除。**

提取规则：

- **全覆盖**：凡帖子涉及大盘方向判断（涨/跌/顶/底/反弹/回调/突破/跌破等），无论措辞强弱，一律提取
- **不合并**：每天重复同一立场也要逐条记录——每次发帖都在影响跟随者，每条都是独立信号
- **预测意图检测（v7 新增）**：区分"预测"和"描述"
  - **预测性**（`predictive: true`）：含"将/会/预计/预判/目标/有望/大概率/看涨/看跌"等前瞻词，或含"明天/下周/年底"等时间锚点，或含"买入/卖出/加仓/减仓"等操作指令
  - **描述性**（`predictive: false` → `specific: "descriptive"`）：纯描述今日行情（"大盘上涨""收阳"）、心理按摩（"不必焦虑""保持耐心"）、自我操作描述无方向指引（"我采用保守策略"）。**不计入评分。**
- **合理标注**：
  - `strength: "strong"` — 措辞坚决（"一定""必将""满仓""清仓""坚决"）+ 给出具体点位/仓位
  - `strength: "moderate"` — 有方向判断但措辞温和（"偏多""倾向于""大概率""有望"）
  - `specific: "explicit_action"` — 给出操作指令（加仓/减仓/买入/卖出/抄底/逃顶）+ 配合个人操作
  - `specific: "directional_clear"` — 明确方向但无操作指令（"明天看涨""调整未结束"）
  - `specific: "directional_vague"` — 方向含糊（"可能反弹但也不排除下跌"），会被脚本排除
  - `specific: "descriptive"` — **v7 新增**：有方向词但无预测意图，会被脚本排除
- **时间维度标注（v7 新增）**：每条信号标注 `time_horizon`
  - `intraday` — "盘中""日内""尾盘""午后" → 当日
  - `short` — "明天""明日""今天""短线""次日" → 1-3 个交易日
  - `medium` — "本周""下周""近期""这波""接下来" → 1-3 周
  - `long` — "牛市""熊市""下半年""明年""趋势""主升浪""年底" → 1 月以上
  - `unspecified` — 无明确时间锚点
- **`specific: "directional_vague"` 和 `specific: "descriptive"`** 不计入评分，**其余全部计入**

#### 4.5.2 运行质量过滤评估

```bash
cd <项目根目录> && python scripts/evaluate_precision.py --blogger <博主名> --quality
```

`--quality` flag 排除 `directional_vague`（模糊观点）和 `descriptive`（描述性非预测），保留 strong 和 moderate 的所有预测性信号。
验证窗口为 T+5、T+10、T+15、T+20 四个时间窗口。对 `time_horizon: "long"` 的信号额外评估 T+40、T+60。

v7 新增时间加权综合评分：每条信号按其 `time_horizon` 分配窗口权重，计算加权综合胜率和收益。短线信号（intraday/short）的 T+20 权重为 0，长线信号（long）的 T+5 权重仅 0.2。

输出按看多/看空分块：
- **看多/抄底能力**：胜率、各窗口收益、最大回撤（买入后最惨浮亏）、收益回撤比
- **看空/逃顶能力**：胜率、各窗口收益、最大反向波动（卖出后最大踏空）、收益/不利比
- **v7 新增**：时间维度分布、时间加权胜率/收益、最优窗口、衰减模式、长线扩展窗口

#### 4.5.3 运行配对交易评估

```bash
cd <项目根目录> && python scripts/evaluate_trade_pairs.py --blogger <博主名> --quality
```

只在高质量信号中配对入场→出场。一笔完整交易 = bullish explicit_action → 下一次 bearish explicit_action。
