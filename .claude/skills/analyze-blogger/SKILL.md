# 博主分析 Skill（方向预测评估）

## 总览

**一句话定位**：全量读取博主帖子，逐条提取其中"对大盘未来的方向预测"（信号），用市场实际走势验证方向对错，并按 `方向 × 实际涨跌幅` 打分（score = direction × return × 100），最后汇总成个体报告与全博主横向榜单。

**五环节流水线**：

| 环节 | 做什么 | 产物 |
|:---|:---|:---|
| ① 提取 | DeepSeek 读帖子，只拎出"明确对未来的方向预测"（方向+周期）；复盘/纯形态/模糊话术不提取 | 信号 `{方向、强弱、指数、周期 spec、摘要、类别 cat}` |
| ② 定参考价 | 发布时刻"当前最新价"：盘中=所处 30 分 bar 开盘价；盘前/午休/盘后/周末=上一根 bar 收盘价 | 参考价 |
| ③ 定验证终点 | 按博主说的周期精确锁死一个验证日——说"明天"就验证明天，不扩展不缩短 | 验证终点 ep |
| ④ 打分 | score = 方向 × 实际涨跌幅 × 100，方向对赚、错亏 | 每条信号一分 |
| ⑤ 汇总/排名 | 个体报告（汇总+四分类表+逐条表）+ 全博主横向榜单 | `reports/*.md` |

**核心术语**：

| 术语 | 含义 |
|:---|:---|
| 信号 | 一条"对未来的明确方向预测"（方向+周期） |
| `spec` | 预测周期编码（`today`/`t1`/`t2`/…/`week`/`month`/`long`/`nd`/`d:日期` 等，见 §3） |
| `cat` | 参与状态：`scored` 计分 / `unscored` 不计分（`spec=long` 恒不计分） |
| 参考价 | 发布时刻"当前最新价"，打分的基准价（§4） |
| 验证终点 | 按预测周期锁定的验证日（§3） |
| 单列 | 不计入分数的信号（unscored/待验证/无效-过时/报错），在汇总中单独列出 |
| 抄底/逃顶平均分 | 底部/顶部拐点当天+前一天窗口内计分信号的平均分（§6） |

**关键分类**（决定哪些进分数）：有方向+有明确周期 → 计分；周期过长 / 目标点位无时间承诺（"看到 4200"没说到哪天）→ `long`/`unscored` 不计分；无周期但有方向 → 单独一档 `nd`（3/5/10 日收益率加权计分，不参与总榜/多空/三档）；数据覆盖不到 / 过时 / 非交易日发布的"今天" → 单列不计分。

**三条铁律**：只验证不预测 · 严格按预测周期 · 诚实打分。

## 用法

```
/analyze-blogger <博主名称> [帖子链接]      # 例：/analyze-blogger 方向评估 奔走的股票
```

- 提供**帖子链接**：先爬取该作者 2026 年至今的帖子，再进入方向评估
- 提供**博主名称**（帖子已爬取）：直接进入方向评估
- 如未提供参数，Skill 会询问。

## 前置条件

**数据就绪 4 要素**：
- `data/posts/<博主名>.json`：已爬取全部帖子，且 `content` 已含完整正文（**标题单独存 `title` 字段**，标题与正文同等重要，提取时两者并列呈现）。正文缺失时用 `scripts/utils/fetch_bodies_shard.py` 抓正文 + `scripts/utils/merge_bodies_to_posts.py` 回填（旧分片归档 `archive/<日期>-bodies-merged/`）
- `data/market/market_data.json`：7 指数日线，已更新到最新交易日（`python scripts/utils/fetch_market_data.py --start 20240601`）
- `data/market/intraday/<指数名>_30min.json`：7 指数 30 分钟线——所有信号的参考价与终点价来源（`python scripts/utils/fetch_market_intraday.py`）
- **DeepSeek API Key**：`export DEEPSEEK_API_KEY="sk-..."`，只经环境变量传入（**绝不写入文件、绝不提交 GitHub**）；依赖 `pip install openai`

**打分前先行检查**：2026 年至今 7 指数的 30 分钟线完整（每指数覆盖 2026-01-01 至最新交易日全部交易日、无缺日）——`run_direction.py` 每次运行自动检查，有缺口先补齐再打分。

**运维要点**（详细操作见对应脚本，此处只留关键）：
- **爬取**：`python scripts/pipeline/scrape_toutiao.py <链接> --since 2026-01-01`（只爬 2026 至今，翻页到早于 since 自动停止）。⚠️ 今日头条风控可能弹验证码并重定向回首页——表现为"爬取成功"但内容是别人的新闻流（`user_info.name` 不是博主）；正文详情页被风控返回空 HTML。爬虫已内置防护（token 从 URL 提取、feed 用户与 `--name` 不符不覆盖、0 条不保存、覆盖前备份到 `data/posts/_backup/`）。重爬后**必须校验内容是否为博主本人帖子**；风控未解除请间隔几小时重试或用登录态 cookie
- **爬取后校验**：`python scripts/utils/verify_posts.py <博主名> --since 2026-01-01`。各 ⚠️ 的含义：重复 id/空字段 → 数据损坏重新爬取；标题型帖多（正文<60字占比高）→ 正文未合并，先抓正文再合并；覆盖 miss（earliest 晚于 since）→ 翻页提前停止重新爬取；备份回归 → 确认后再继续。**任一 ⚠️ 未解决时先修数据，不要带病评估**

## 评估工作流

### Step 1：加载数据

读入 `data/posts/<博主名>.json` 的全部帖子。之后按需从 `data/market/market_data.json` 中读取与验证日期对应的行情行（无需全量加载，按日期查找即可）。

### Step 2：自动提取信号（DeepSeek）

信号由 `scripts/pipeline/extract_signals_direction.py` 调用 DeepSeek flash 按 §1~§8 规则自动逐条提取（不再人工逐条标注）：

```bash
export DEEPSEEK_API_KEY="sk-..."   # 只经环境变量，绝不写入文件
cd <项目根目录>
python scripts/pipeline/extract_signals_direction.py <博主名> --runs 3
```

脚本做的事：
1. 读 `data/posts/<博主名>.json` 帖子（过滤 `publish_date >= 2026-01-01`），每条以「标题：…\n正文：…」并列呈现（标题取 `bodies.title` → `title` 字段 → 无正文时的原 `content`），标题与正文同等重要
2. 分批（默认 15 条/批）调 DeepSeek，按 §1~§8 规则判定并标注 `d`/`s`/`spec`/`idx`/`cat`（schema 见 §2）
3. 脚本强校验：非法 `spec`/`idx` 丢弃、`cat` 归一、同帖重复与同日同周期同方向去重、`summary≤50字`
4. **信号自查**：把「已提取信号 + 原文」回喂 DeepSeek 独立审查（keep/fix/drop/补加），修掉漏结论（如 07-28 丢了"探底回升我看涨"）、周期误套等错误
5. 产出 `data/direction_signals/<博主名>.json`，随后运行 `python scripts/eval/run_direction.py <博主名>` 生成报告

> **正式入库用 `--runs 3`**：DeepSeek 同 prompt 下每次运行有少量批间随机差异（信号数 ±3 量级）。`--runs 3` 完整跑 3 次（提取+自查），保留 ≥2 次运行都出现的信号后合并，聚合指标（正确率/平均分）跨运行稳定（实测两组独立 3 次共识结果差异在 ±1 个百分点内）。运行元数据写 `data/direction_signals/_<名>_run.json`（gitignored，仅本地溯源）。
>
> **冒烟测试**：`--limit 30` 只处理前 30 条；`--out /tmp/x.json` 写指定路径不动正式数据；`--dry-run` 不调 API；`--no-verify` 跳过自查（更快）。每次运行会覆盖目标文件（无增量续跑）。
>
> **质量边界**：自查能系统性修复"漏结论/周期误套/单列类缺失"等错误（与人工标注精确同键从 63 提升到 ~67），但**不能保证每条语义正确**——方向冲突帖（全文立场与单句结论相反）仍会偶发分歧，且每次运行有少量随机差异。聚合层面（正确率/平均分）与人工标注一致；如需逐条精确可核查，需人工抽检。

## 打分规则（§1~§8，与引擎 `run_direction.py` 一一对应）

**整个过程不能用关键词匹配或正则表达式来筛选或标注。** 每一条帖子的每一个标注字段，都必须由 DeepSeek（通过本脚本）理解帖子语义来判定，而非依赖关键词列表——§1~§8 即写入 DeepSeek system prompt 的标注契约。

### §1 提取为信号的核心原则

**提取核心原则**：信号 = 帖子中**明确对未来的方向预测**。LLM 不应机械地逐项检查，应整体判断：**这篇帖子表达了对大盘未来的明确方向预测吗？** 是 → 提取；否 → 不提取。
- 模棱两可 → 忽略：方向不明、涨跌皆可，如"可能涨也可能跌""不好说""边走边看""看市场情绪""不确定"
- 纯复盘 / 对过去分析 → 忽略：回顾行情、评价已发生走势、事后总结（"今天这波下跌说明……""这次探底回升很标准"）
- 仅仅描述形态 → 忽略："震荡""筑底""洗盘""蓄势""拉锯""考验X点支撑""探底回升""冲高回落"
- 同一帖子里既有复盘又有明确未来预测 → 只提取未来预测部分
- 整篇立场含糊但夹带明确预测句 → 提取该预测句（如"后市难料，但明天我看涨" → 提取"明天看涨"）
- "震荡"不代表明确方向；"震荡下跌/震荡上涨"才表示有明确方向
- 有明确的预测点位和预测周期 → 视作有明确方向预测：预期点位高于参考价=看涨、低于=看跌（例："今天下午能站上4000"→看涨）

**参与打分的核心原则**（针对已提取的信号，判定细节见 §2/§3）：
- 有明确的预测方向和预测周期（明天/本周/下周/短期等）→ `cat=scored`，按周期计分
- 有明确的预测点位和预测周期 → `cat=scored`，按周期计分
- 没有明确预测周期但有方向 → `cat=scored`，`spec=nd`（独立档，3/5/10 日收益率加权计分，不参与总榜/多空/三档）
- 有方向但周期偏长（"中长期""未来几个月""三年"）或目标点位无时间承诺 → `spec=long`、`cat=unscored`，不计分（详见 §2）

**默认规则**：帖子中未写明任何指数或板块的名称，默认该帖子是对上证综指/大盘的判断，应提取信号。

**信号时间范围**：只提取 2026 年 1 月 1 日及之后发布的信号。

**参与打分的博主**：帖子跨度的时间 ≥ 6 个月、且 2026 年以来可提取的信号数量 > 50 条的博主才参与打分；不满足者不参与打分。

### §2 信号标注字段

信号写入 `data/direction_signals/<博主名>.json`，schema（引擎 `scripts/eval/run_direction.py` 直接读取）：

```json
{"blogger": "博主名", "signals": [{"pub": "2026-01-04 15:16", "d": 1, "s": 1, "idx": "上证指数", "spec": "t1", "summary": "指数开门红的概率大", "cat": "scored"}]}
```

| JSON 键 | 语义字段 | 取值 |
|:---|:---|:---|
| `pub` | `publish_time` | 帖子发布时间（posts JSON 中对应 `publish_date` 字段，格式 `YYYY-MM-DD HH:MM`，用于定位参考价 bar） |
| `d` | `direction` | `1` = bullish 看多；`-1` = bearish 看空 |
| `s` | `strength` | `2` = strong（措辞坚决："一定""必将""满仓""清仓""坚决""毫无疑问"）；`1` = moderate（有方向判断但措辞温和："偏多""倾向于""大概率""有望"） |
| `idx` | `target_index` | 数据 key 名（默认"上证指数"）；若帖子明确提到某指数/板块则按下方映射表标注对应指数 |
| `spec` | `time_horizon` | 预测周期编码，见 §3 表（`t1`/`t2`/`t3`/`t5`/`tN`/`today`/`week`/`nweek`/`nweek_first`/`month`/`nmonth`/`long`/`nd`/`d:YYYY-MM-DD`）。**精准对应帖子中预测本身的时间周期**，不从宽泛分类中选取——LLM 必须从帖子原文中提取博主明确说的时间，按 §3 规则转换 |
| `summary` | 信号内容摘要 | ≤50 字的预测关键句概括 |
| `cat` | 参与状态 | 只有两个值：`scored` = 参与打分；`unscored` = 不计分（**spec=`long` 的信号一律 `cat=unscored`**）。**`待验证` / `无效-过时` / `报错` 不需要 LLM 手写**：终点超出数据覆盖、或过时（终点 ≤ 发布日且已收盘）、或非交易日发布的"今天"仍写 `cat="scored"` 且 `spec` 必填，由引擎计算时自动判定并单列 |

**⚠️ 语义理解原则（关键）**：预测周期必须通过**语义理解**提取——是帖子中对未来的**预测周期**，而不是关键词匹配。帖子中出现"明天"二字不代表这就是对明天市场的预测。例如：
- "明天会怎样，先看4000反击" → ✅ 预测明天 → 预测周期=明天
- "**明天开始**至本周五，两手准备" → 预测的是**本周** → 预测周期=本周（"明天"只是起止描述）
- "本人**还剩4成**仓位" → ❌ 仓位自述，不是预测 → 不提取
- "**接下去**每跌50点加0.5成" → ❌ 仓位计划，不是市场方向预测 → 不提取
- "**下个目标是4260点**" → ⚠️ 目标点位无时间承诺 → 标 `spec="long"` + `cat=unscored` 单列不参与打分

> LLM 必须先回答"这篇帖子预测了什么？"，再回答"这个预测针对什么时间周期？"

**目标点位 vs 时间预测（统一规则，§3 引用）**：博主常用"目标是 X 点""看到 X 点""还有 X 点空间"表述——这些是**目标点位**，只承诺方向，不承诺到达时间。**不能**把目标点位当成"未来几天/下周"预测。无时间承诺的目标点位统一标 `spec="long"` 单列（`cat=unscored`，不参与打分）；帖子明确说"X 天内到 4260"（有明确时间 → 按对应预测周期正常打分）才计分。

**板块 → 指数映射规则**：帖子中提到具体板块/宽基指数时，只有**能映射到下表的指数**（7 个映射指数 + 默认的上证综指）的预测才参与打分，其余板块预测忽略：

| 帖子提到的名称 | 映射指数 | 代码 |
|:---|:---|:---|
| 创业板 / 创业板指 / 创业板ETF | 创业板指 | 399006 |
| 科创 / 科创50 / 科创板 | 科创50 | 000688 |
| 双创 | 创业板指+科创50（各半）| 399006/000688 |
| 小盘 / 成长 / 中证1000 | 中证1000 | 000852 |
| 中证500 | 中证500 | 000905 |
| 上证50 / 50ETF | 上证50 | 000016 |
| 老登 / 大金融 / 银行 / 保险 / 券商 / 证券 / 白酒 / 酒 | 上证50 | 000016 |
| 沪深300 | 沪深300 | 000300 |
| 上证综指 / 上证 / 综指 | 上证指数 | 000001 |

> **老登板块映射到上证50**：博主口中的"老登"指大盘蓝筹（银行、保险、券商、白酒等），与上证50 指数高度相关，故映射到 000016。
>
> **其余不可映射的板块忽略**：有色、钢铁、医药、创新药、恒科、半导体、电池、房地产、航天、军工等无法映射到下表指数的板块预测，不参与打分。
>
> **双创计算方式**：分别用创业板指和科创50 按同一发布时刻（同一参考价 bar）、同一终点日计算各自的 return，取两者**算术平均**作为该信号的 return，再按 §5 公式打分。

**7 指数数据表**（`idx` 取值 = `market_data.json` 中的 key，代码见上方映射表）：`上证指数` 000001（大盘基准）/ `上证50` 000016 / `沪深300` 000300 / `中证500` 000905 / `中证1000` 000852 / `创业板指` 399006 / `科创50` 000688。

> **读取方式**：找到对应的 key 后，查找 `日期` 字段等于验证日的行，取 `开盘`/`收盘`/`最高`/`最低`/`成交量` 字段。

### §3 验证终点

**核心原则**：帖子预测的时间窗口是什么，就验证那个窗口的终点——说"明天"就只看明天，说"下周"就只看下周，**不扩展、不缩短、不随意假设**。LLM 必须根据帖子的具体预测周期确定一个精确的验证日期，不能泛化到长度区间。

> **"信号日"指帖子发布的自然日**。下表所有"信号日之后第 N 个交易日"均从发布日往后数：周五盘后说"明天涨"→ 明天=周六 → 顺延验证周一；周日说"明天/星期一"→ 验证周一。参考价仍按 §4 定价。

**预测周期 → 验证终点的判定规则**：

| 帖子中的预测周期 | 编码 | 验证终点 |
|:---|:---|:---|
| "今天""今日""下午""今天尾盘" | `today` | 信号日当天收盘（必须是交易日发布的信号，否则报错） |
| "明天""明日""次日" | `t1` | 信号日之后第 1 个交易日 |
| "后天" | `t2` | 信号日之后第 2 个交易日 |
| "下周""下周一""下周五" | `nweek` / `nweek_first` | 下一周的对应交易日（"下周一"=`nweek_first`=下周第一个交易日；"下周五"=`nweek`=下周最后一个交易日；"下周"未指明星期几 → `nweek`，下周最后一个交易日） |
| "本周""本周内" | `week` | 当周（非交易日发布→下一交易周，见下方说明）的最后一个交易日 |
| "月底前""月末前" | `month` | 当月最后一个交易日 |
| "下个月""下月" | `nmonth` | 下个月的最后一个交易日 |
| "下半年""全年""今年""2026年"等年度预测 | `long` | **不参与打分**（`cat=unscored`） |
| "N天后""N日内"（N 为具体数字，如"3天后""10天后"） | `tN` | 信号日之后第 N 个交易日（"3天后"→`t3`、"10天后"→`t10`） |
| "1-2天""3-5天"等"X-Y天" | `tY` | 信号日之后第 Y 个交易日（**取预测窗口的最后一个交易日**。博主的原意是"X~Y天内涨"，取第 Y 天验证：如"1-2天"→`t2`、"3-5天"→`t5`） |
| "未来几天" | `t3` | 信号日之后第 3 个交易日（博主未给具体数字，默认 3 天） |
| "近期""短期" 且无具体数字 | `t5` | 信号日之后第 5 个交易日（博主未给具体数字，保守默认） |
| "中长期""未来几个月""三年"等 | `long` | **不参与打分**（`cat=unscored`） |
| **"X月X日""X月X日之前""X月X日前后"（未来具体日期）** | `d:YYYY-MM-DD` | **该日期本身**（若为非交易日则顺延至下一个交易日） |
| **"下周X""周五"等具体星期（未来）** | `d:YYYY-MM-DD` | **对应的具体日期** |
| 无预测周期但有明确预测方向 | `nd` | 信号日后第 3/5/10 个交易日收益率（相对参考价）加权平均计分；独立档，不参与总榜/多空/三档 |
| **"目标是X点""看到X点""还有X点空间"（目标点位，无时间承诺）** | `long` | **不参与打分**（`cat=unscored`，详见 §2） |

> **⚠️ 区分未来日期与回顾日期**：帖子中出现日期不等于预测。必须判断该日期是**对未来的预测窗口**（"8月7日之前都是磨底"→ 预测到 8/7）还是**对过去的回顾**（"2月8日我还提醒了一次"→ 回顾，不提取）。同一日期在预测语境中才标注为具体日期。

> **周末/顺延处理**：验证终点当日若该指数无行情行（周末、长假、临时休市），一律顺延到下一个有行情行的交易日——如周五盘后说"明天涨"→ 验证周一。该顺延规则用于 `tN`、`d:` 具体日期类；`today` 类终点**必须发布于交易日**（非交易日发布的"今天"由引擎报错单列，不计分）；`week`/`nweek`/`nweek_first`/`month`/`nmonth` 类本身按交易日历取周期内最后（或首个）交易日，不另行顺延。另：信号日为周末/假期时，"本周"验证**下一交易周**最后交易日；"月底前"验证发布**自然月**最后交易日——若月末已无剩余交易日则该预测已过时（引擎判"无效-过时"）。

> **⚠️ 过时预测（通用）**：凡验证终点 ≤ 发布日（且发布日已收盘）的信号即过时——典型场景：周五盘后发"本周"（当周已结束）、月末已无剩余交易日发"月底前"、把回顾日期误标为具体日期、盘后发"今天"。LLM 无需过滤，引擎侧防御：此类信号自动标注"无效-过时"单列，不计分。

> **数据覆盖检查**：验证终点必须不晚于 `data/market/market_data.json` 中对应指数的最后一行日期。若终点超出数据覆盖范围，该信号由引擎自动判定为"待验证"（LLM 仍写 `cat="scored"`、`spec` 必填），不参与打分与汇总，在 §7 汇总表中单列。

### §4 信号参考价

**信号参考价 = 当前所能获取的最新价格**。所有预测周期统一用此参考价：

| 信号时间 | 参考价 |
|:---|:---|
| **交易时间中**（9:30~11:30、13:00~15:00） | **所处 30 分钟 K 线的开盘价**（bar 时间 = 收盘时间，如 10:20 发布 → 所处 10:30 bar，取该 bar 开盘价） |
| **非交易时间**（盘前 <9:30 / 午休 11:30~13:00 / 盘后 ≥15:00 / 周末假期） | **上一根 30 分钟 K 线的收盘价**（如 15:30 发布 → 15:00 bar 收盘价；盘前/非交易日 → 上一交易日 15:00 bar 收盘价） |

> **30 分钟线结构**（`data/market/intraday/<指数名>_30min.json`）：每指数每日 8 根 bar（10:00/10:30/11:00/11:30/13:30/14:00/14:30/15:00），bar 时间 = 收盘时间，首根 bar open≈9:30 开盘价、末根 bar close=当日收盘价。信号参考价与终点价均取自此。
>
> 终点价为验证终点日 15:00 bar 收盘价（= 当日收盘价）。`双创` 取创业板指 + 科创50 各算 return 后取算术平均。无 30 分钟数据时引擎退回日线口径（最新收盘价）。

### §5 打分规则

**score = direction × return × 100**

```
return    = 验证终点收盘价 / 信号参考价 − 1
direction = +1（看多）/ −1（看空）
```

> 参考价按 §4 取当前所能获取的最新价格（交易时间中→所处 30 分钟 K 线开盘价；非交易时间→上一根 30 分钟 K 线收盘价）；终点收盘价 = 验证终点日 15:00 bar 收盘（即当日收盘价）。

**示例**：

| 情形 | 强度 | 参考价 | 终点收盘 | return | direction | 打分 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| 看多，涨了 | moderate | 3800 | 4020 | +5.79% | +1 | **+5.79** |
| 看多，跌了 | **strong** | 3800 | 3760 | -1.05% | +1 | **-1.05** |
| 看空，跌了 | moderate | 4100 | 4072 | -0.68% | -1 | **+0.68** |
| 看空，涨了 | **strong** | 4100 | 4120 | +0.49% | -1 | **-0.49** |

**无周期方向（spec=`nd`，独立档）**：无明确时间点 → 用 **3/5/10 日收益率加权平均**衡量预测兑现度：

```
r3  = 信号日后第 3 个交易日收盘 / 参考价 − 1     # 短线兑现
r5  = 信号日后第 5 个交易日收盘 / 参考价 − 1     # 中短兑现
r10 = 信号日后第 10 个交易日收盘 / 参考价 − 1    # 中长兑现
return = (r3 + r5 + r10) / 3                    # 等权平均
score = direction × return × 100
```

> r3/r5/r10 各自与**同一参考价**（§4）比较，衡量不同持有期的累计涨幅/跌幅；等权平均后乘以方向计分。验证覆盖要求第 10 个交易日落在数据范围内，否则引擎判"待验证"。`nd` 独立成档：不参与总榜/看多/看空/三档，仅在「无周期方向档」统计并排名；抄底/逃顶平均分**保留 nd**（拐点定位与周期无关）。逐条表中 `nd` 行的 终点日 显示 `3/5/10日`、终点收盘=第 10 日收盘、备注=`多点加权`。

### §6 汇总指标

对博主的所有预测信号汇总（**只统计显式周期计分信号**（spec≠`nd`）；无周期方向 `nd` 独立成档、unscored/无效-过时/待验证/报错信号单列，均不计入任何指标）：

```
信号总数：N（显式周期）
  另有：无周期方向 nd X 条（独立档，3/5/10 日收益率加权计分，不参与总榜/多空/三档）/ unscored X 条（spec=long）/ 无效-过时 X 条 / 待验证 X 条 / 报错 X 条（单列，不计分）
方向正确：N（正确率 N% = score>0 的信号数 / (N − 平数)；score=0 计"平" X 条，平数不计入分子分母）
  - strong 正确：N/N（正确率 N%）
  - moderate 正确：N/N（正确率 N%）
平均分：+X.XX（= 单信号平均收益 %，核心指标）
波动率：X.XX（单信号 score 样本标准差，n-1 分母）
夏普：+X.XX（= 平均分 / 波动率；信号 <2 条或波动率为 0 时显示 —）
最高分：+X.XX / 最低分：-X.XX
看多平均分：+X.XX（N 条）  看空平均分：+X.XX（N 条）
抄底/逃顶平均分：+X.XX（N 条）= 底部/顶部拐点当天及前一天（共 2 个交易日）内信号的平均分
```

> 抄底/逃顶的拐点（顶部/底部，含 Major + Intermediate）取自 `knowledge/market_analysis.md`（§5.1/§5.2）；窗口 = 拐点交易日 + 其前一交易日（共 2 个交易日），信号发布时间落在该窗口内的计分信号参与统计；窗口内无信号时显示 —（0 条）。

```
|:---|:---|:---|:---|:---|:---|:---|:---:|:---:|:---:|:---:|:---:|:---|
| 1 | 01-07 | 上攻已显疲态，将进入回调 | ↓ | mod | 明天 | 上证 | 4083 | 01-08 | 4072 | -0.27% | +0.27 | — |

```

> **备注列**：正常信号填 `—`；盘中"今天"（日内窗口计分）填 `日内`；spec=`long` 的不计分信号（中长期/未来几个月/三年、目标点位）填 `不计分`；spec=`nd` 的无周期方向填 `多点加权`；验证终点超出数据范围填 `待验证`；验证终点 ≤ 发布日且已收盘（过时预测）填 `无效-过时`；非交易日发布的"今天"填 `报错`（`待验证`/`无效-过时`/`报错` 均由引擎自动判定）。unscored/无效-过时/待验证/报错信号不参与打分与 §6 汇总；`nd` 独立成档只在「无周期方向档」统计。方向正确 = 验证终点收盘优于参考价（score>0），验证重点在终点。

### §8 报告输出

**个体报告**：`python scripts/eval/run_direction.py [博主名]`（不传参数则跑全部博主）→ `reports/<博主名称>_direction.md`，含：
- 头部：评估时间（= 最新交易日）、帖子总数（posts 缺失时标"未知"）、信号总数
- 汇总指标：按 §6
- **四个分类表**（每表含 信号数/平均分/胜率/波动率/夏普）：① 按预测指数（上证指数/上证50/科创50/创业板指/双创等）；② 按预测周期三档归类（0-1个交易日（今天/明天）/2-5个交易日（1周内）/6个交易日及以上（大于1周），"今天（盘前/盘中）"在 0-1 档下单列子行，**无周期方向 nd 独立成档不混入三档**，在三档表下方单列一行）；③ 按看多看空；④ 按抄底逃顶（抄底=底部拐点当天+前一天窗口内信号、逃顶=顶部拐点当天+前一天窗口内信号，拐点取 `knowledge/market_analysis.md`，**抄底/逃顶保留 nd**）
- 月度表现：按信号发布月份统计
- 信号时间分布与集中度（⚠️ 必须提出警告）：覆盖 <3 个月 ⚠️覆盖不足；单月占比 ≥50% ⚠️高度集中、33%~50% 轻度集中；相邻月份缺 ≥3 个月 ⚠️严重缺口、缺 1-2 个月提示。典型场景：停更/减产、帖子数据缺失、标注未完成
- 逐条汇总表：按 §7
- 观察要点：正确率结论、多空对比（看多/看空平均分）、抄底/逃顶表现、最强/最弱三档与指数、最大单条命中/失误、单列信号统计

**横向对比**：`python scripts/eval/comparison_all.py` 生成 `reports/comparison_direction.md`，只需要各榜单（**口径 = 显式周期信号**，无周期方向 nd 独立成档）：
- **总榜**（按平均分排序，附计分信号数/正确率/**波动率/夏普**/多空数）——**排名资格：显式周期计分信号 ≥ 30 条 且 平均分 > 0.1**，不足者不参与排名、单列注明（统计无意义）
- **按预测周期分类的三档归类，各档排名**（每档按平均分排序的榜单，含"其中：今天（盘前/盘中）"子榜）——**各档排名资格：该档信号 ≥ 10 条 且 平均分 > 0.1，各档排名仅取前10名上榜；各档排名表采用与总榜相同的表格形式（排名/博主/信号数/正确率/平均分/波动率/夏普/看多/看空）**；无周期方向 nd 独立成档不进入三档
- **方向榜单**：看多榜 / 看空榜（信号子集榜单：看多= d=1、看空= d=-1；资格与表格形式同各档排名；子集方向固定故不含看多/看空列）
- **无周期方向榜**（spec=nd，无明确时间点、3/5/10 日收益率加权计分；资格与表格形式同方向榜单，独立排名）
- **信号覆盖/集中度警告**（同上述阈值，逐博主列出）

**预测周期三档归类的详细算法**（实现位置：`scripts/eval/run_direction.py` 的 `bucket_of()`，`comparison_all.py` 直接复用，与引擎共用同一交易日历与 prev_td 逻辑）：

```
交易日历 CAL = market_data.json 中"上证指数"的日期序列（升序）
基准日 base = pub_date 若 pub_date ∈ CAL，否则 = 其前最近一个交易日
跨度 span = CAL.index(ep) − CAL.index(base)     # 信号日→验证终点的交易日数量
分档：span ≤ 1 → 0-1个交易日（今天/明天）| 2 ≤ span ≤ 5 → 2-5个交易日（1周内）| span ≥ 6 → 6个交易日及以上（大于1周）
子行：spec = today 的信号，在 0-1 档下方单列"其中：今天（盘前/盘中）"
无周期方向：spec = nd 的信号不入三档，`bucket_of()` 直接返回「无周期方向」独立成档

边界示例：
  - 周五发布"明天"→ ep=下周一，span=1 → 0-1 档
  - 周一发布"下周初"→ ep=下周一，span=5 → 2-5 档
  - 周一发布"下周"→ ep=下周五，span=9 → 6+ 档
  - 周六发布"明天"→ base=周五，ep=下周一，span=1 → 0-1 档
```

## 附录：各博主 LLM 阅读指导

逐条提取前，先按博主的帖子结构特征快速定位核心预测句。

**通用规则**：
- **标题与正文同等重要**——帖子以「标题：…\n正文：…」并列呈现，标题常直接给出预测结论（陈述句标题如"明天看涨""站稳4130就能到4250"可直接提取）；疑问句/引流话术式标题（"明天A股会怎么走？""下周要变天？"）不代表预测，去正文找结论。标题里明确的方向/周期不要因正文冗长而漏掉
- 在**标题 + 正文**中快速提取方向与预测周期即可，行情回顾、纯复盘、投资理念、仓位自述不提取
- **注意同一帖子可能出现多个观点**（不同周期**或不同方向**，如"明天探底回升、下周继续涨""短期看空、长期看多"）——每个"观点+周期"分别记一条信号，各按 §3 设验证终点、按 §5 打分；同一周期重复表述只记一条
- 同一天发布的针对同一周期的相同方向的预测，只记一条（如一天内多帖都喊"明天中阳线"→记一条，保留当天最晚发布的一条）
- 同一天发布的针对不同周期的预测，分开记录；针对不同周期的不同方向的预测，分开记录
- 不同日期发布的信号都分开记录

> **通用注记**：对列表接口只回标题、预测结论在**详情页正文**的博主（下表中标注"结论在正文/详情页正文"者），若 `content` 仍未合并进完整正文，先按「前置条件」的正文补齐流程（分片抓取 + 合并）再标注；标题疑问句本身不代表预测。

## 注意事项

- **只验证、不预测**——你的任务是评估博主的过去预测准确率，不是对未来走势发表观点
- **严格按预测周期验证**——帖子说"明天"就只看明天，不扩展到 3 天
- **打分即收益**——方向对了赚 return、错了亏 return
- **诚实打分**——博主预测准确率低就说低，不要粉饰
- **代码与文档一致性**：本文件 §1~§8 与 `run_direction.py` 一一对应；若修改任一规则，需同步另一方（引擎自测：`python scripts/eval/run_direction.py --selftest`）
